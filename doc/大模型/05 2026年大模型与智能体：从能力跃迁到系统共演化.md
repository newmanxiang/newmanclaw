## 一、感知错位：为什么看得见效果，看不见逻辑

### 1.1 一个普遍的认知困境

过去半年，从业者面对的不是"没有进展"，而是**进展太多、层次混杂**。模型名字三个月换一代，Benchmark 表每周刷新，智能体产品从 CLI 扩到云端 VM、从单会话扩到事件驱动的常驻系统。体感上确实更强了——长任务更能撑住、少打断、少跑偏、更能自己改自己的错。但把这些体感还原成技术机制时，常见的解释几乎都停在表层：

- "参数更大了"——解释不了 Grok 4.6 这种**基座不变、只做后训练**的跃迁
- "上下文更长了"——解释不了同样 1M 窗口下，Opus 4.6 在 MRCR 上把 Sonnet 4.5 从 18.5% 拉到 76% 的质量差
- "工具更多了"——解释不了 2026 年 9 月那篇对 11 个生产级编码 harness 的源码审计结论：没有一家用通用 Agent 框架，也没有一家用向量检索来找代码
- "开源追上闭源了"——解释不了 Kimi 自己都承认的那句话：K3 整体仍落后于 Fable 5 和 GPT-5.6 Sol，差距不在单项分数，而在"品味"和长程判断

表层叙事失效，是因为 **2026 年真正改变的不是某一个旋钮，而是三个旋钮开始互相改对方。**

### 1.2 把"效果"还原成系统问题

第一篇提出过：智能体场景下能力衰减是乘法式的。一个 10 步任务，单步正确率从 95% 降到 90%，端到端成功率从 60% 跌到 35%。这个公式在 2026 年没有过时，但它漏了一项：

```
2025 年的心智模型：
  Agent ≈ 模型 + 提示词 + 工具

2026 年的真实系统：
  Agent = 模型 × 训练分布 × 运行时（harness）
```

"看得见效果"通常发生在乘积上：任务成功率、会话时长、一次做对的比例。"看不见逻辑"是因为乘积的三个因子同时在变，而且彼此是输入：

```
更好的模型  →  允许更简单的 harness（少编排、少脚手架）
更好的 harness →  产生更高质量的轨迹数据
更好的轨迹   →  训练出假设特定 harness 存在的下一代模型
```

这是一条闭环，不是三条平行赛道。不看见这条闭环，就只能被动跟进每一次发布。

## 二、2026 年真正的范式转移：三层共演化

先给结论，再展开机制。

> **2026 年大模型与智能体的主线，不是"模型更聪明了"，而是架构、后训练、运行时三层开始共演化。能力跃迁发生在乘积上；单看任何一层都会误判。**

```
┌─────────────────────────────────────────────────────────────────┐
│  运行时层  Harness Engineering                                   │
│  上下文工程 · Skill/MCP · 记忆/压缩 · 子智能体 · 沙箱 · 事件驱动   │
│  代表：Claude Code / Codex / dsh / Cursor Cloud Agent            │
├─────────────────────────────────────────────────────────────────┤
│  训练层    Post-training 成为主杠杆                               │
│  环境派生 mid-train · 在真实 harness 里做 Agentic RL              │
│  领域专家 + on-policy 蒸馏 · 用上一代模型再生 SFT 轨迹            │
│  代表：DeepSeek-V4 两段式后训练 / Grok 4.6 纯后训练升级           │
├─────────────────────────────────────────────────────────────────┤
│  架构层    为"百万上下文 + 长程推理"重写 Transformer               │
│  混合注意力（CSA/HCA、KDA）· 残差流扩宽（mHC、AttnRes）           │
│  极端稀疏 MoE · Muon 优化器 · 量化感知训练                       │
│  代表：DeepSeek-V4 / Kimi K3 / Qwen3.8-Flash-Next                │
└─────────────────────────────────────────────────────────────────┘
         ↑ 每一层都在改另外两层的约束条件
```

三层各自回答一个不同的瓶颈：

| 层 | 2025 年底的瓶颈 | 2026 年的回答 |
|:---|:----------------|:--------------|
| 架构 | 推理时计算把序列拉得很长，标准注意力的二次方代价把 1M 上下文和长思维链变成经济上不可行 | 混合注意力压缩 KV；残差流扩宽提升深度信号；稀疏 MoE 把激活参数和总参数解耦 |
| 训练 | 预训练收益递减；SFT/RLHF 教的是"会说"，不是"会在环境里连续行动" | 把可验证环境变成训练分布；在真实 agent loop 里做 RL；后训练单独就能换代 |
| 运行时 | 提示词塞不下工具定义、历史、记忆和中间结果；长任务在上下文腐烂中失败 | 把上下文当成稀缺资源来经营；把循环、沙箱、技能、子智能体做成操作系统 |

下面三节把每一层拆到具体机制。不追求把所有发布列全，只保留能说明机制的样本。

## 三、架构层：推理时计算撞墙之后，Transformer 被重写

### 3.1 为什么架构重新成为主战场

第二篇的核心判断是：推理时计算打开了"用钱换智能"的弹性维度。这个判断被 2026 年完整验证——几乎所有前沿模型都把 `effort` / `reasoning_effort` 做成一等公民，从 `low / medium / high / max` 一直加到 `xhigh` 和 `ultra`。

但第二篇当时没有充分展开的约束是：**推理时计算的燃料是 token，而 token 的代价由注意力机制决定。** DeepSeek-V4 论文把这件事写得很直白：test-time scaling 被标准注意力的二次复杂度卡住了；与此同时，长程智能体和工作流又要求百万级上下文。两股力量同时加压，架构必须改。

所以 2026 年架构创新的目标函数变了。不再是"同样数据下把 MMLU 再抬两个点"，而是：

```
在可接受的单 token FLOPs 和 KV cache 预算内，
支撑 1M 上下文 + 长思维链 + 多轮工具调用。
```

这解释了为什么今年的技术报告里，出场最多的不是新的 tokenizer 或新的位置编码，而是三类东西：**混合注意力、残差流、稀疏 MoE。**

### 3.2 混合注意力：把 KV 从"存全部"改成"存能用的"

标准多头注意力对每个新 token 都要和全部历史做点积。序列到 1M，KV cache 和计算都会爆。2026 年的主流解法不是再发明一种注意力，而是**把不同层做成不同的压缩策略，让局部精度和全局覆盖分工**。

**DeepSeek-V4 的 CSA + HCA：**

- **Compressed Sparse Attention（CSA）**：先沿序列维压缩 KV，再做 DeepSeek Sparse Attention（DSA）。稀疏选择由 FP4 lightning indexer 完成，只让真正相关的块进入注意力。
- **Heavily Compressed Attention（HCA）**：KV 压得更狠，但注意力本身保持稠密——用更粗的全局视图换稳定性。
- 层调度（V4-Pro 默认）：前两层 HCA 打底，其后 CSA / HCA 交错；MTP 预测块只用滑动窗口注意力。

效果是可核验的工程数字，不是宣传语：在 1M 上下文下，V4-Pro 相对 V3.2 只需 **27% 的单 token 推理 FLOPs 和 10% 的 KV cache**；更小的 V4-Flash 进一步到 10% FLOPs / 7% KV。百万上下文从"实验室能力"变成"可以日常打开"。

**Kimi K3 的 KDA + Gated MLA：**

93 层里 69 层用 Kimi Delta Attention（一种混合线性注意力），24 层保留 Gated MLA。线性注意力把序列复杂度从二次降到近线性，官方称百万上下文解码最高可快 6.3 倍。这和 DeepSeek 是同一类问题的不同解：DeepSeek 走"压缩 + 稀疏选择"，Moonshot 走"大部分层改线性、少数层保留精确注意力"。

**共同逻辑：** 长上下文的真正瓶颈不是"窗口声明了多少"，而是"KV 能不能养得起、注意力还能不能对准"。第一篇说的"信息带宽 ≠ 认知带宽"，在 2026 年被工程化成了 KV 压缩与稀疏检索问题。

### 3.3 残差流扩宽：深度网络的信号公路被加宽

注意力解决的是**序列方向**上的信息流。另一件事是**深度方向**：层数堆上去之后，梯度与表征会在残差通道里衰减或互相抵消。2026 年两家开源旗舰不约而同改了残差。

**mHC（Manifold-Constrained Hyper-Connections，DeepSeek-V4）：**

普通残差是 `x ← x + F(x)`。Hyper-Connections 把残差流从 `d` 维扩成 `n_hc × d`（V4 里 `hc_mult = 4`），用三个映射分别处理"读入层、残差混合、写出层"。朴素扩宽会在深层堆叠时数值爆炸。mHC 的关键约束是把残差混合矩阵投影到**双随机矩阵流形**（Birkhoff polytope）上：行和列都为 1、元素非负，谱范数 ≤ 1，因而前向和反向都不扩张。投影用 Sinkhorn-Knopp 迭代（约 20 步）。这是用几何约束换训练稳定性，让"更宽的残差公路"在万亿参数规模上可训。

**AttnRes（Attention Residuals，Kimi K3）：**

不沿残差流扩宽，而是**跨层选择性地取回表征**，而不是让每一层均匀累加。官方称训练效率约 +25%，额外算力 < 2%。它解决的是同一类问题：深度增加后，早期层的信息被后期层淹没。

两家路径不同，问题是同一个：**当模型既要变深又要变长，残差不再是实现细节，而是一阶架构变量。**

### 3.4 极端稀疏 MoE：总参数和激活参数彻底解耦

MoE 不是新闻。新闻是稀疏比被推到以往会被认为训不稳的区间：

| 模型 | 总参数 | 激活参数 | 专家结构 | 稀疏特征 |
|:-----|:-------|:---------|:---------|:---------|
| DeepSeek-V4-Pro | 1.6T | 49B | DeepSeekMoE + 前 3 层 Hash-MoE | 亲和度从 Sigmoid 改为 Sqrt(Softplus) |
| DeepSeek-V4-Flash | 284B | 13B | 同上 | 用更小激活打推理任务 |
| Kimi K3 | 2.8T | 104B | 896 专家选 16，Stable LatentMoE | Quantile Balancing，去掉敏感的负载均衡超参 |
| Qwen3.8-Flash-Next | 125B | 6B | 下一代 Qwen4 架构预览 | 训练成本约为上代 1/9 |
| GLM-5.3-Flash | 320B | 18B | 稀疏注意力 + 线性注意力混合 | 首个原生多模态 GLM-5 |

三件事值得单独说：

**Hash-MoE bootstrap（V4）。** 前几层不用学习到的 router，而用冻结的 `token_id → expert_id` 哈希表。早期层的路由本来就不稳定，与其让一个随机初始化的门控去"猜"，不如用确定性哈希把流量铺开，后面的层再交给可学习 top-k。这是工程对理论的修正：路由是能力，但也是噪声源；噪声最大的地方先不要学。

**Quantile Balancing（K3）。** 专家分配直接由 router 分数的分位数决定，不再依赖一套容易漂的负载均衡超参。稀疏比到 16/896 时，路由和优化从"实现细节"变成一阶问题。

**量化感知训练成为默认。** V4 的专家权重走 FP4、其余多为 FP8；K3 从 SFT 起就用 MXFP4 权重 + MXFP8 激活。2.8T 的 K3 权重约 1.56 TB，不是事后有损量化，而是训练出来的精度。开源旗舰能被推理厂商接住，这一步是前提。

### 3.5 优化器与训练基础设施：Muon 从论文走进标配

AdamW 统治了整个 GPT 时代。2026 年 DeepSeek-V4 和 Kimi K3 都把 **Muon**（以及 K3 的 Per-Head Muon）写进正式配方。Muon 用正交化更新方向，收敛更快、深层更稳。它能进生产，是因为训练框架补齐了配套：混合 ZeRO、细粒度重计算、mHC 的融合核、确定性 kernel（保证训推 bit-wise 可复现）。

架构创新如果没有训推一体的基础设施，会停在论文。V4 论文用整整一节讲 fused MoE kernel、TileLang、异构 KV（含落盘）和前缀复用。K3 为了 KDA 的前缀缓存，直接给 vLLM 贡献实现，官方 API 在编程负载下缓存命中率超过 90%。**架构、系统和产品定价被同一条效率曲线拴在一起。**

### 3.6 架构层的一句话

2026 年的架构创新，本质是给"长上下文 × 长推理 × 稀疏计算"找到可部署的交点。谁先把 1M 上下文的 KV 和 FLOPs 降到日常可承受，谁就先把推理时计算从"贵的能力"变成"默认能力"。这正是第二篇预判的弹性维度，补上了当时没写透的成本约束。

## 四、训练层：后训练成为主杠杆，环境成为新的数据源

### 4.1 一个标志性事实：Grok 4.6 没有换基座

2026 年 8 月的 Grok 4.6 是后训练升级，不是新的基础模型。SpaceXAI 做了三件事：更长的补量训练、用 4.5 **按不同 reasoning effort 和不同 agent harness 再生 SFT 轨迹**、再在真实智能体环境里做 RL（知识工作、通用编码、内核优化、Web、CAD）。Intelligence Index 从 56 提到 61，与 GPT-5.6 Sol Max 打平。

这件事的含义比分数更大：

> 当基座已经足够强，**换代可以发生在后训练。** 而高质量后训练数据，越来越不是人类写的示范，而是"上一代模型 × 真实 harness × 可验证环境"共同滚出来的轨迹。

这把第一篇"不要在模型层建壁垒"的判断推进一步：连厂商自己都不把壁垒完全放在预训练上了。

### 4.2 DeepSeek-V4 的两段式后训练

V4 的后训练是目前公开信息里最完整的"工业级配方"：

1. **分领域独立培养专家。** 数学、代码、Agent、指令遵循各自走 SFT → GRPO（带领域奖励模型）。
2. **On-policy 蒸馏合成统一模型。** 学生模型对教师专家做 reverse KL，把分散的专长压回一个权重。

这不是 2024 年那种"拿一堆混合数据再 SFT 一遍"。它承认一个事实：Agent 需要的能力分布太宽，一个奖励模型管不好所有领域；先专精再合并，比从头训一个全能策略更稳。Flash 和 Pro 在推理任务上靠近，在知识和高难度 Agent 任务上仍拉开——说明**总参数主要买的是知识容量，推理深度可以用 thinking budget 部分补偿。** 这与第二篇"推理时计算是乘数、精调不是主赛道"一致，只是把"精调"替换成了更结构化的后训练。

### 4.3 训练分布从"人类任务"转向"环境本身"

传统 Agent 训练有两个瓶颈：专家轨迹贵，人工设计的任务和 verifier 覆盖窄。2026 年学术和工业同时在找同一扇门：**让环境自己产生可验证目标。**

**State2State（2026.08）** 的做法几乎朴素：用探索策略在环境里收集可复现状态，把"从状态 A 走到状态 B"做成任务，成功与否用状态匹配判定，无需人类指令或教师模型，再用 GRPO 训练。它作为 mid-training 单独有用，作为后续人类任务 RL 的初始化更有用，并出现跨环境迁移的迹象。

**EvoTrainer** 把问题再翻一层：Agentic RL 里标量奖励会掩盖多种失败模式，所以**策略和训练侧 harness 必须一起进化**——诊断脚本、回测、可复用 skill 都是训练系统的一部分，而不只是被训练的模型。最大增益出现在长程 SWE 任务上，这几乎是在实验室里预演工业界已经在做的事。

**Grok / Kimi / Claude 的工业对应物：** 不是在 FrozenLake 里走格子，而是在内核优化、编译器、CAD、仓库级软件工程、办公文档这些**有真实反馈的环境**里滚轨迹。K3 用早期版本承担团队自己的 kernel 优化；Fable 5 用最小视觉 harness 打通《火红》；这些 demo 的技术含义是——**可验证的长程环境，已经是训练数据的主矿。**

### 4.4 模型开始为特定 harness 而训练

K3 的 limitation 写得很诚实：它在"保留思维历史"的模式下训练；如果 harness 不回传历史 thinking，或中途从别的模型切过来，生成质量会极不稳定。建议用验证过的 harness（如 Kimi Code），并避免会话中途换模型。

这不是小毛病，这是共演化的证据：

```
模型假设：thinking 块会被完整回传
harness 假设：模型会在 thinking 里做计划，而不是把计划写进可见回复
两者一旦错配，乘法链条在第 0 步就断
```

Moonshot 评测时按任务选用 Kimi Code / Claude Code / Codex；DeepSeek 宣称 V4-Pro 针对 Codex 做了优化并支持 Responses API 与 Anthropic 格式。**Benchmark 已经变成"模型 × harness"的联合评测。** 离开声明的运行时谈分数，会把系统能力误认为模型能力——这也是为什么同一模型在不同 CLI 里体感能差出一个档。

### 4.5 Effort 成为训练目标，而不只是推理开关

2026 年所有旗舰都暴露 effort。表面是产品功能，底层是训练目标变了：模型必须学会**按任务难度分配思考量**。Opus 4.6 引入 adaptive thinking——不再是"开/关 extended thinking"，而是模型自己判断这次该想多深。GPT-5.6 在 `max` 之上加了 `ultra`：默认四个子智能体并行，用空间换时间。

Adaptive thinking 直接回击了第一篇批评的 auto 路由：把"这条任务该给谁"从弱路由器前移到**执行模型自己的元认知**。路由器在没有深入理解问题时做难度预判，必然系统性误判；让正在解题的模型决定想多深，信息是对称的。当然，它仍可能对简单题想得过多——所以才需要可调的 effort，把元认知从黑盒变成可控旋钮。

## 五、运行时层：Harness 从工具变成平台

### 5.1 一个定义，以及为什么 2026 年要专门为它命名

2026 年初行业开始把这件事叫做 **Harness Engineering**：

> Agent = 模型 + harness。  
> Harness 是把 LLM 耦到世界的运行时：循环、工具、上下文管理、安全控制、编排、扩展面。

2026 年 9 月的源码研究（arXiv:2609.00006）解剖了 11 个生产级编码 harness（Claude Code、Codex CLI、Gemini CLI、Mistral Vibe、OpenHands、Aider、Mini-SWE-Agent、Hermes、Pi、OpenCode、OpenClaw），外加一个 meta-harness 对照。两个空缺在把语料扩到约四百万行之后仍然成立：

1. **没有任何一家导入通用 Agent 框架**（LangChain 那一类）。
2. **没有任何一家用向量 embedding 检索代码。**

字段跑在手写的异步循环和确定性检索上。上半年的纵向对比还显示：收敛正在变成模仿，行为策略从提示词散文迁到配置。论文的命题是：**2026 年上半年，编码 harness 完成了从工具到平台的转向。**

这与第一篇结尾"少一些框架，多一些真正的智能"并不矛盾——要少的是**外置工作流框架**，要多的是**与模型共演化的、手写的、针对真实循环的运行时**。LangChain 式的抽象层解决的是"把 Agent 概念映射成类"，生产 harness 解决的是"如何在 KV cache、权限、压缩、子智能体和前缀缓存的硬约束下活过 8 小时任务"。

### 5.2 上下文工程：把窗口当成操作系统的内存

2026 年最被低估、但对长程 Agent 最致命的技术，不是新工具，而是**上下文经营**。Claude 官方 cookbook 把三件套写进了 API：compaction、tool-result clearing、memory。Claude Code 的实现则是一条分级管道——先用最便宜的手段腾空间，不得已才上重型压缩：

```
每次请求前：
  1. 工具结果预算（截断过大的 tool_result）
  2. 历史剪裁
  3. Microcompact：清掉不再被需要的旧工具结果
  4. Context collapse：投影出折叠视图，不改原始消息
  5. Auto-compact：生成摘要，替换旧历史
  6. 仍然超限 → 有界恢复，而不是无限重试
```

几个机制值得单独理解，因为它们决定了"长任务为什么突然能跑完"：

**Microcompact 与缓存冻结。** 30 分钟前读过的文件内容，多半不再有用，却可能占掉几千 token。替换文本一旦随轮次变化，前缀缓存的 key 就变了。所以"这条 tool_result 已被压缩"必须按 `tool_use_id` 冻结，不能每轮重写一遍。**上下文工程首先是缓存工程。**

**Session-memory compact 先于全文摘要。** 先尝试保留尾部、把更早的内容写入会话记忆，而不是一上来就用一段 summary 覆盖全部历史。全文摘要是不可逆的信息损失；能推迟就推迟。

**Skill 的渐进披露。** 第三篇已经论证：100 个 Skill 的元数据大约 5000 token，细节按需展开。MCP 把工具 schema 一次性塞进窗口，Skill 把"怎么做"留在提示层按需加载。2026 年的生产实践站在这一边：11 家里 Skill 的采用（9/11）略高于 MCP（8/11）。MCP 没有消失，它回到了"连接层"该在的位置。

**1M 窗口没有取消上下文工程。** K3 在 BrowseComp 上用 300K 触发压缩拿到 91.2，全 1M 无管理是 90.4。窗口变大降低了压缩频率，但不改变"有效认知带宽 < 名义带宽"。Opus 4.6 把 8-needle 1M MRCR 从 Sonnet 4.5 的 18.5% 拉到 76%，说明**真正的突破是长上下文利用率，而不只是窗口规格。**

### 5.3 四种 harness 哲学：同一个词汇表，不同的中心

到 2026 年 8 月，编码 Agent 的词汇表已经统一：模型、工具、循环、上下文、Skill、子智能体、权限、沙箱。分化发生在**以谁为中心**：

| 系统 | 架构中心 | 它真正在问的问题 |
|:-----|:---------|:-----------------|
| Claude Code | 把一个 Claude Agent 做强 | 如何让同一个智能体更稳、更长、更好用 |
| Codex | Agent + 执行运行时 | 如何让智能体在真实计算机里行动，同时不失去环境控制 |
| DeepSeek Harness (`dsh`) | 可组合运行时 | 如何让模型、工具、循环、沙箱、UI 都成为可替换插件 |
| Cursor Cloud Agent | 隔离 VM + 编排 + 验证 | 如何让常驻智能体在事件上醒来、把目标坚持到完成，并交出可验证产物 |

**Claude Code** 把生命周期控制做深：hooks、permissions、agent teams（并行子智能体，适合读多写少的任务如代码评审）、接管子会话的 tmux 交互。它是产品，扩展类型是分裂的（Skill / command / hook / MCP 各有清单）。

**Codex** 把边界做显式：沙箱、审批、在真实机器上的执行权限。OpenAI 同时把 `ultra` 做成模型侧的多 Agent 模式，把一部分编排推进权重内部。

**dsh（2026-08-13，MIT，Cordis 内核）** 的口号是 Everything is a plugin：模型适配器、工具注册表、会话日志、**连 agent loop 本身**都是插件。更有战略意味的不是"替代 Claude Code"，而是它提供 `dsh-subagent-claude-code` 和 `dsh-hooks-claude-code`——用官方 Agent SDK 把 Claude Code 跑成子智能体，并直接执行已有的 `.claude/hooks.json`。这是**运行时层的互联**，不是模型层的对打。

**Cursor** 把 Cloud Agent 做成隔离 Linux VM：独立克隆、独立上下文、子智能体可分到各自的机器；订阅 PR / Slack / 定时事件；`/goal` 让目标跨会话存活；Agent 构建完软件后自己跑、自己测，并把录像附在 PR 上。模型（Composer、GPT、Claude、Gemini、Grok）在 harness 之下可替换。产品主张非常明确：**模型是引擎，harness 是车。**

四种哲学会共存。对企业，这意味着"选一个 Agent 产品"越来越像"选一个操作系统发行版"：应用生态、权限模型、扩展机制和运维方式，比底层用哪颗 CPU 更难迁移。

### 5.4 从单循环到系统：子智能体、常驻、事件

2026 年下半年，harness 的能力边界从"一次会话里的 ReAct 循环"扩成"一个能活很久的系统"：

- **子智能体有独立上下文。** 这是目前对抗上下文腐烂最有效的结构手段：主 Agent 保留目标与约束，子 Agent 在干净窗口里做探索，只把结论传回来。代价是协调与合并——Fable 5 / GPT-5.6 ultra / Claude agent teams / Cursor 分 VM 子智能体，都在付这笔税。
- **常驻目标。** Cursor 的 `/goal`、Cloud Agent 自动订阅自己开的 PR 并修到 CI 绿，把 Agent 从"一问一答"变成"拿到完成条件之前不解散"。
- **事件驱动。** 监控 PR、Slack 线程、定时任务。智能体开始有"休眠—唤醒"语义，而不只是用户按回车。
- **产物即证据。** 会用自己写的软件、会附上演示录像，把"我改完了"从自然语言声明变成可检查的 artifacts。这是评测体系向运行时的渗透。

第一篇把未来 Agent 比作自动驾驶：需要高精地图、交通规则、乘客确认目的地。2026 年的 harness 就是在把这三样装进运行时——记忆与知识文件是地图，权限与沙箱是交通规则，compaction / 人机接管是确认与纠偏。模型更强，这些部件没有消失，反而被标准化了。

## 六、格局重绘：闭源的判断力、开源的效率、Flash 的基础设施化

### 6.1 一条必须先画清的分界

到 2026 年 9 月，把所有模型排成一张"谁最强"的表会误导决策。真正的分界是三条：

```
闭源旗舰（Fable 5 / GPT-5.6 Sol / Opus 5）
  → 长程判断、品味、少打断、安全与产品完整性
开源旗舰（Kimi K3 / DeepSeek-V4-Pro / GLM-5.x）
  → 可权重、可自建、成本数量级更低，长程 Agent 已进入可用区
Flash / Luna 层（Qwen3.8-Flash、GLM-5.3-Flash、GPT-5.6 Luna、Gemini Flash）
  → 高频、低价、原生多模态，正在成为 Agent 系统的"CPU"
```

K3 官方评测自己写：整体仍落后 Fable 5 和 GPT-5.6 Sol，体感差距大于单项分数差距。这与第一篇的 `>>` 是同一类现象——**乘法链条末端的"自觉性"和"判断力"，仍然是闭源旗舰最硬的壁垒。** 开源追平的是编码、检索、工具调用这些可验证子任务；尚未追平的是"知道什么时候该停、该问、该换策略"。

### 6.2 半年时间线（只保留改变机制的节点）

| 时间 | 事件 | 机制含义 |
|:-----|:-----|:---------|
| 2026-02 | Claude Opus 4.6：1M 上下文（beta）、adaptive thinking、effort、compaction、agent teams | 旗舰第一次把长上下文、自适应思考、上下文压缩做成产品原语 |
| 2026-04 | DeepSeek-V4 Preview：CSA/HCA、mHC、Muon、1M 上下文开源 | 开源侧给出"百万上下文可日常化"的架构答卷 |
| 2026-05 | Cursor Composer 2.5；知识供给篇（本系列 04）发布 | 产品侧模型用用户轨迹做长程 RL；知识供给被明确为编译时理解问题 |
| 2026-06 | Claude Fable 5 / Mythos 5：代际能力 + 安全回退架构 | 能力强到必须用另一颗模型做领域熔断；长程自主成为主指标 |
| 2026-07 | GPT-5.6 Sol/Terra/Luna；Kimi K3 开源 2.8T | 产品家族按档位拆分；开源第一次进入 3T 量级并原生多模态 |
| 2026-08 | Grok 4.6 纯后训练升级；dsh + V4-Pro GA；Qwen3.8-Flash 与 GLM-5.3-Flash 同日开源 | 后训练可换代；harness 开源平台化；Flash 进入生产力主路径 |
| 2026-08/09 | Cursor Cloud Agent：事件订阅、分 VM 子智能体、`/goal` | 常驻系统成型 |
| 2026-09 | Harness Engineering 源码审计论文 | 学科被命名，经验被写成解剖 |

### 6.3 闭源旗舰在优化什么

Fable 5 相对 Opus 4.8 的宣传重点不是又一个编码榜，而是：**任务越长、越复杂，领先越大。** Stripe 在 5000 万行 Ruby 仓库里用它做全库迁移；记忆加文件后，在《Slay the Spire》上的增益是 Opus 4.8 的三倍；最小视觉 harness 打通《火红》。这些例子指向同一项能力：**在稀疏反馈下维持目标、杀死错误信念、用自己的笔记改进后续步骤。**

GPT-5.6 把同一问题拆成产品结构：Sol 做长程，Terra 做日常，Luna 做体积；`ultra` 把并行子智能体做成官方模式。命名从"一个模型一个号"变成"代际号 + 耐久档位"，允许档位按自己的节奏升级。这是在承认：**用户买的不是一个权重文件，是一条能力—成本—延迟的帕累托前沿。**

安全第一次成为能力架构的一部分。Fable 5 与 Mythos 5 是同一颗模型；公开面在网络与生物等主题上熔断到 Opus，Mythos 走受信通道。K3 在 Moonshot 内部榜上约 10% 的任务撞上 GPT-5.6 Sol 的网络护栏。**下一代壁垒不全是智能，还有"智能被允许用在哪里"。**

### 6.4 开源旗舰在优化什么

K3、V4、GLM、Qwen 的共同策略是 **效率换智能**：同样的长程任务，用更少的激活参数、更小的 KV、更激进的量化、更高的缓存命中。K3 API 缓存命中输入 $0.30 / MTok，编程场景官方命中率 > 90%，实际输入价被缓存结构决定，而不是被标价决定。

开源的战略价值因此变了。2024–2025 年开源的意义是"能跑接近 GPT-4 的东西"；2026 年是：

1. **可审计的架构与配方**（V4 论文、K3 技术报告），让整个行业的下一轮训练有公共台阶。
2. **可重组的运行时**（dsh），让闭源 Agent 也能被嵌进开源内核。
3. **可承受的单位智能成本**，让 Flash 级模型进入每小时成千上万次的工具循环。

许可仍是分水岭：K3 对超 2000 万美元营收的 MaaS 和超大规模产品有额外条款；GLM 路线更接近宽松开源。对企业自用，条款影响很小；对要转售推理的平台，这是真约束。

### 6.5 Flash 不是旗舰的廉价影子

8 月 26 日 Qwen3.8-Flash-Next 与 GLM-5.3-Flash 同日开源，定位已经不是"聊天便宜一点"。Qwen 125B 只激活 6B，训练成本约为上代 1/9；GLM 320B-A18B 把视觉编程、办公交付物（PPTX/PDF/DOCX/XLSX）写进卖点，API 价到旗舰的 1/10。Google 一侧则是 3.6 Flash / 3.5 Flash-Lite 先 GA，3.5 Pro 作为多 Agent 编排器反复延期——**编排器可以晚，工人必须先便宜。**

这验证了第一篇的三层市场：Market 1（基础推理）的商品化速度确实比多数人预期更快，而且商品化首先发生在 Flash 层。Agent 系统会自然长成：

```
Frontier 模型：计划、裁决、长程责任
Flash 模型：检索、格式转换、短工具循环、高并发子任务
```

第一篇批评的 auto 模式，失败点是用弱模型在任务开始前做路由。正确结构是：**主责任始终在强模型，Flash 只承接已被切好的、边界清晰的子任务。** GPT-5.6 ultra 和 Claude agent teams 都更接近后者。

## 七、对前四篇判断的复盘

写年度调研如果只往前看，会把去年的正确判断和过时判断混在一起。需要明确复盘。

### 判断仍然成立的

**乘法衰减。** 长任务仍然放大单步差距。Fable 5 "任务越长领先越大"是这条定律的产品表达。

**推理时计算是乘数。** effort / adaptive thinking / ultra 成为所有旗舰的标配。第二篇的主线被验证。

**评测比模型本身更稀缺。** 现在连官方榜都要注明 harness。企业如果还用 MMLU 做选型，会系统性地选错。第一篇"投资评测体系"的优先级应该再提高一档。

**知识覆盖仍是企业侧最弱因子。** 1M 窗口和 Memory 降低了检索管道的必要性，但私域知识的显性化、结构化、适配化（第四篇的三层转译）没有被取消。Skill 和 LLM Wiki 路线在 2026 年更顺，而不是更不需要。

**不要在模型层建死壁垒。** Grok 4.6 证明后训练就能换代；dsh 证明运行时可以同时挂 Claude 和 Codex。可替换性从口号变成了结构。

### 需要修正的

**"少框架、多模型"要加限定。** 少的是外置工作流框架。生产上出现的是更厚的 harness，而且它正在平台化。正确表述是：**少编排脚本，多运行时原语；模型变强会减少 workflow 节点，但不会减少上下文、权限、记忆、沙箱这些操作系统级部件。**

**大上下文会削弱 RAG，但不会让上下文工程消失。** 第二篇中期预判"10M+ 窗口让 RAG 必要性下降"方向对，节奏上 2026 年先到了 1M 可用。真正下降的是"把仓库切成 chunk 做向量检索"这条路——生产编码 Agent 已经不用它。留下的是按需文件、Skill、记忆和压缩。

**中端趋同、顶端分化。** 第一篇说中端会趋同、顶级仍差异化。2026 年 9 月这张图更清楚：Flash 层快速商品化，Fable / Sol 仍在判断力和长程连贯性上收费。开源旗舰卡在中间——足够替代大量 Opus 4.x 工作负载，但还不是 Fable 的替代品。

**Auto 路由的失败被"自适应思考 + 子智能体"部分修复，但没有被"便宜路由器"修复。** 不要把 2025 年的 auto 模式和 2026 年的 effort / ultra 混为一谈。

## 八、未来方向：下一阶段的瓶颈已经可见

以下判断按"机制已经出现苗头、尚未成为默认"来写，不做时间表。

### 8.1 下一条缩放定律：模型 × harness 联合训练

当前多数实验室仍是"先训模型，再适配 harness"。K3 对 thinking 回传的敏感、V4-Pro 对 Codex 的优化、Grok 用多种 harness 再生轨迹，都在走向反面：**训练分布必须包含运行时。**

下一步会更彻底——循环策略、压缩策略、工具预算、子智能体拓扑，都会进入可学习范围。EvoTrainer 已经在训练侧把 harness 当作共同进化对象。谁先把"在哪个压缩阈值下该摘要、哪类任务该拆子智能体"训进模型，谁就能在相同权重下拉开长程成功率。

对买方的含义：绑定将发生在"模型 + 官方 harness"组合上，而不是模型 API 上。保持可替换，要测的是组合，不是单独的权重。

### 8.2 验证，而不是生成，会成为稀缺能力

生成已经便宜。长程 Agent 的失败越来越不是"不会写"，而是"写了但没有可靠的完成判定"。State2State 用状态匹配当奖励，工业界用测试、CI、截图、录屏、形式化规格。下一代差距会集中在：

- 过程监督是否覆盖真实失败模式（标量奖励不够）
- 环境是否可复现（同一任务两次结果能比）
- 模型是否会主动设计实验来证伪自己

第一篇把元认知放在金字塔顶层。2026 年的产品语言是"少问、多做、自己改错"。2027 年左右更关键的会是：**它凭什么知道自己改对了。**

### 8.3 在线学习与持续记忆：从会话内到跨任务

V4 论文把高效长上下文称为探索 online learning 的必要基础。Fable 5 的文件记忆把游戏成绩放大三倍。Cursor 的 `/goal` 让目标跨会话存活。缺的是权重层面的持续更新——今天的"记忆"几乎都在上下文和文件系统里，不在参数里。

两条路线会并行：一条继续把记忆当作 harness 子系统（可审计、可删除、可合规）；一条探索参数侧的局部更新（快，但难审计）。企业会先接受前者。第四篇的"编译时理解"在这里会碰到新问题：编译周期如果从"人写 Skill"变成"Agent 每天重写自己的知识文件"，知识基础设施就要按**日频产物**来设计，而不是按文档库来设计。

### 8.4 多 Agent 从插件变原语

ultra、agent teams、分 VM 子智能体、dsh 把 Claude/Codex 当 provider，都在把"一个循环"拆成"一个过程"。尚未解决的是标准：如何描述任务图、如何合并冲突、如何把预算分给子树、如何在子智能体越权时熔断。ACP 已经在部分系统里出现第三角色——harness hosting。协议层会再走一轮 MCP 当年走过的路：先有事实实现，再有互操作。

风险也对称。GPT-5.6 系统卡指出它比 5.5 更容易越出用户意图；再给它并行代理权，范围控制必须先于能力释放。Fable 的领域熔断是同一逻辑在模型层的实现。

### 8.5 从编码 Agent 到知识工作 Agent

编码是 2025–2026 年的主战场，因为反馈密：测试要么红要么绿。2026 年下半年的旗舰发布已经把办公、研究、金融分析、视觉交付物放到和编码并列的位置。知识工作的反馈疏——一份行业研究报告没有编译器。谁能把疏反馈环境也变成可训练、可评测的 harness（第四篇意义上的知识供给 + 本篇的验证器），谁就能把 Agent 从工程师工具变成企业默认劳动力接口。

Flash 模型进入办公主路径，说明经济账已经算得过来。缺的是组织和流程：权限、审计、责任归属、人机交接。这些不是模型问题，是 Market 3 的问题。

### 8.6 世界模型与具身：仍然不是主线，但不再是科幻

Fable 5 用视觉打通游戏、做 CAD、做物理仿真；K3 做芯片和编译器；Mythos 5 在蛋白设计上匹配熟练人类操作者。这些仍是"在工具环里的世界"，不是机器人学意义上的世界模型。但对架构师有一个清晰信号：**接地气的闭环（看屏幕、跑仿真、读仪器）比再堆一层语言推理更能打开新任务族。** 企业应把"哪些业务有可观测、可执行、可回放的环境"当作 Agent 落地的筛选条件。

### 8.7 安全与能力将继续孪生

公开旗舰带熔断，Mythos / Flash Cyber 走受信通道，双用途能力不再以同一接口出售。合规、评测、护栏会成为 Market 2 的默认模块。忽略这一层的技术规划，会在采购和上线阶段被挡回来。

## 九、给架构师的行动建议

把上面的机制收成可执行的优先级。不重复前四篇已经说过的"别绑死模型、要建评测"，只写 2026 年 9 月之后应追加的部分。

**1. 以"模型 × harness"为选型单位。** 测 Claude 就要在 Claude Code（或官方 Agent SDK）里测；测 K3 就要保证 thinking 回传；测 V4-Pro 要声明 Codex / dsh / 自研循环中的哪一种。分数不可比时，用自己的长任务集在同一运行时里比。

**2. 把上下文工程当成平台能力，而不是提示词技巧。** 工具结果预算、分级压缩、会话记忆、Skill 渐进披露、前缀缓存友好的消息布局，应落在模型网关 / Agent 运行时，而不是每个项目各写一套。这是第一篇 Market 2 在 2026 年的具体形态。

**3. 主模型不要路由掉，子任务可以 Flash。** 责任链的根节点用旗舰（判断、停、问、改）；被切开的、有明确输入输出的子任务用 Flash。不要用弱模型做任务前路由。

**4. 知识供给按"日频产物"设计。** Skill、AGENTS.md、记忆文件、评测集，应假设 Agent 会读也会写。权限和评审流程要按代码来，而不是按 Confluence 来。这是第四篇终局判断的工程化。

**5. 先选有验证器的场景。** CI、监控、对账、配置合规、回归测试——能自动判定成败的环境，才能吃到 2026 年这轮 Agentic RL 的红利。疏反馈场景（战略研究、方案评审）仍然需要人在环上，用旗舰模型，而不是用更复杂的 workflow 去假装有验证器。

**6. 开源旗舰用于可替换与成本，闭源旗舰用于责任链顶端。** K3 / V4 / GLM 已经能覆盖大量编码与工具循环；Fable / Sol / Opus 5 仍值得放在架构裁决、长程无人值守、对外交付物这些乘法链条最长的位置。混合部署的"不可感知"原则仍然有效，但调度粒度应从"每个请求"改为"每个目标 / 每个子树"。

**7. 把 harness 选型提升到与云厂商选型同级。** 一旦 Skill、hooks、记忆文件、权限模型、事件订阅绑上去，迁移成本会高于换一个模型 API。dsh 这类插件内核的价值，是把迁移从"重写 Agent"降成"换一组插件"。值得跟踪，但不要在 developer preview 上赌生产。

## 十、收尾：从跟发布，到看闭环

回到开头的感知错位。

近半年真正发生的事，不是名字变得更快，而是三条曾经分开的曲线交在了一起：

- 架构把百万上下文和长思维链的成本打下来，推理时计算才成为默认而不是奢侈；
- 后训练把真实 harness 和环境反馈变成数据，模型开始为"会在循环里活很久"而优化，而不是为"下一句更像人"；
- 运行时把上下文、技能、记忆、子智能体、沙箱做成平台，Agent 从一次会话变成一个系统。

所以你会看见效果——因为乘积变了。也会觉得逻辑不好抓——因为任何一篇发布说明都只动了三个因子里的一个。

把观察点从"又发布了什么模型"挪到下面三个问题，跟进就会从被动变成可预测：

1. **这次发布降低的是哪一种成本？** KV、激活参数、后训练、还是长任务失败率？
2. **它假设了什么样的运行时？** thinking 是否必须回传？是否依赖官方压缩？是否为某个 CLI 调过？
3. **它把验证器放在哪里？** 测试、CI、状态匹配、人类偏好，还是什么都没有、只靠更长的思考？

三个问题能回答，机制就露出水面；机制露出水面，下一步往哪走就不需要等下一场发布会。

> 2026 年的智能体，已经不是"更强的聊天模型外挂了工具"。它是架构、后训练与运行时共同长出来的系统。壁垒不在抓住某一个权重文件，而在抓住这条共演化闭环：可验证的环境、可经营的上下文、可替换的模型，以及知道自己何时是对的。
