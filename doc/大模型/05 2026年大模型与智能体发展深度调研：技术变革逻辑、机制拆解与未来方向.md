## 一、从体感说起：2026 年变的不是 p，是 n

### 1.1 一个被忽视的量级变化

第一篇写作时（2026 年 3 月），我对智能体任务的体感尺度是这样的：一次架构分析、一次方案评审、一次多文件重构——大约 10 到 20 步工具调用，一个会话完成。那时的乘法表停在 n = 20。

半年后，任务的尺度变了：

- Stripe 用 Fable 5 在一天内完成 5000 万行 Ruby 代码迁移
- Kimi K3 的技术报告披露，单条 RL 训练轨迹达到**数千次工具调用、百万 token**
- Opus 4.8 的 dynamic workflows 让模型自己写编排脚本，调度**数十到数百个子 agent**
- 独立长程评测显示，主流模型的可用任务长度已进入 H > 200 的区间

这不是"任务变复杂了一点"。从 n = 20 到 n = 200 是一个数量级的跨越，而在乘法公式下，数量级的跨越对单步可靠性 p 提出的要求不是线性的。

### 1.2 重算乘法表：n 每增长 10 倍，允许的错误率下降 10 倍

第一篇的表格问的是"给定 p，n 步后成功率是多少"。现在要反过来问：**给定目标成功率，n 步任务要求 p 至少是多少？** 由 S = p^n 解出 p = S^(1/n)：

| 任务步数 n | 成功率 50% 所需 p | 允许的单步错误率 | 成功率 90% 所需 p | 允许的单步错误率 |
|:----------|:-----------------|:---------------|:-----------------|:---------------|
| 10 | 93.3% | 6.7% | 98.95% | 1.05% |
| 20 | 96.6% | 3.4% | 99.47% | 0.53% |
| 50 | 98.6% | 1.4% | 99.79% | 0.21% |
| 100 | 99.31% | 0.69% | 99.89% | 0.11% |
| 200 | 99.65% | 0.35% | 99.95% | 0.05% |
| 500 | 99.86% | 0.14% | 99.98% | 0.02% |
| 1000 | 99.93% | 0.07% | 99.99% | 0.01% |

这张表揭示了 2026 年一切变化的起点：

**事实一：从 n = 10 到 n = 200，允许的单步错误率从 6.7% 压到 0.35%，下降了近 20 倍。** 2025 年一个"很好用"的模型，单步错误率大约在 3%–5%。要支撑 200 步任务，它的每一步都必须比原来可靠一个数量级以上。这不是"再训练好一点"能达到的，需要方法论层面的变化。

**事实二：在 n 很大时，p 的微小差异决定生死。** p = 99.5% 和 p = 99.0% 在 10 步任务上几乎无差别（95% vs 90%），在 200 步任务上是 37% vs 13%。第一篇说"95% 和 90% 之间有鸿沟"，现在鸿沟移到了 99.5% 和 99.0% 之间。**这解释了为什么 2026 年的 benchmark 差距看起来只有两三分，而实际体感差距仍然巨大**——Terminal-Bench 上 57.9 与 55.8 的差异背后，是长程任务上截然不同的完成率。

**事实三：n 的增长同时抬高了成本。** 每一步都要消耗 token，且每一步的上下文都包含之前所有步的历史。n 增长 10 倍，如果每步成本不变，总成本增长 10 倍；如果每步成本随上下文线性增长（全注意力的情形），总成本增长 100 倍。

所以 2026 年的核心命题可以用一句话概括：

> **如何在成本可承受的前提下，把单步错误率压低一个数量级，并让它在数百步的上下文增长中不衰减。**

模型层、训练层、harness 层、部署层的所有变化，都是对这个命题的分头作答。

## 二、第一性原理：长程智能体的四个约束方程

在逐一分析各家做了什么之前，先把这个命题拆成可以独立分析的方程。它们不是我发明的，而是从 S = p^n 出发做最直接的展开。

### 2.1 可靠性方程

```
S = ∏ p(L_i)        i = 1 … n
```

第一篇把 p 当作常数。这是一个必须修正的简化。第一篇第二章第 3 项"上下文利用有效性"已经指出：模型对长上下文中间信息的注意力衰减，信息越多越容易"看了但没理解"。这意味着**单步可靠性是上下文长度 L 的减函数**——p(L) 随 L 增长而下降。

而在智能体任务中，L 不是常数：每一步都往上下文追加工具返回、命令输出、文件内容。第 i 步的上下文长度 L_i = L_0 + i·ΔL，随步数线性增长。于是可靠性方程变成 ∏ p(L_i)，比 p^n 衰减得更快——**越到任务后期，每一步越不可靠**。

这个修正有实证支撑：Opus 4.6 与 Sonnet 4.5 在 1M 上下文的 MRCR v2 上分别是 76% 和 18.5%。两个模型在短上下文上的能力差距远没有这么大；差距是 p(L) 的斜率不同造成的。

### 2.2 成本方程

```
C = Σ c_i,   c_i ≈ price_read · L_i + price_gen · t_i
```

第 i 步的成本由两部分组成：读入上下文 L_i 的成本，加上生成 t_i 个 token（思考 + 输出）的成本。把 L_i = L_0 + i·ΔL 代入求和：

```
C ≈ price_read · (n·L_0 + n²·ΔL/2) + price_gen · Σ t_i
```

**第一项是 n 的二次函数。** 当 n 从 10 涨到 200，这一项涨 400 倍。这就是为什么长程 agent 的账单主要不是"生成"而是"反复读入历史"，也是为什么 Fable 5.1 把 cache read 价格砍掉 75% 是一个针对长程 agent 的精准动作——在这个方程里，price_read 是主导变量。

**第二项由每步生成 token 数 t_i 决定。** 推理时计算把 t_i 推高（更多思考 token 换更高的 p），effort 参数就是控制 t_i 的旋钮。tokenizer 变化（Opus 4.7 同文本 token 数 1.0–1.3 倍，Sonnet 5 再涨 30%）等比例放大所有项。

成本方程告诉我们：**要让 n = 200 的任务经济可行，必须让 c_i 与 L_i 解耦（注意力与 KV 的成本不随上下文线性增长），并且让 t_i 可控。**

### 2.3 校验方程

第二篇给出了推理时计算提升 p 的公式：

```
p' = 1 − (1 − p)^k · (1 − p_v)
```

k 是探索的候选路径数，p_v 是验证器的有效性。这个公式有一个 2026 年才充分暴露的隐含前提：**验证器 p_v 必须存在**。数学题有答案，代码有测试，所以第二篇讨论的场景中 p_v 天然存在。但智能体在真实环境中的一步——"把这个配置改成 X"、"给用户回复这段话"、"点击这个按钮"——在推理时**没有现成的验证器**。没有 p_v，公式退化为 p' = 1 − (1 − p)^k，多路径采样的收益急剧下降，而成本仍然是 k 倍。

再叠加成本方程：推理时计算把每一步的 t_i 放大 k 倍，在 n = 200 时总成本再乘 k。**推理时计算是"在考场上多检查几遍"的策略，但 200 步的任务每步检查 3 遍，时间与预算都不够。**

于是校验方程给出一个严格推论：

> **在长程任务中，验证必须从推理时移到训练时。** 也就是让模型在训练阶段面对带验证器的环境，把"检查"练成"直觉"，使推理时的单次前向传播就具有接近 p' 的可靠性。

这个推论就是 agentic RL 的第一性原理——它不是"又一种训练技巧"，而是校验方程在长程约束下的唯一解。

### 2.4 学习方程

```
p_{t+1} = p_t + α · Δ(经验)
```

以上三个方程都在描述单个任务内部。但一个真正有用的智能体应该在任务之间进步——第 t+1 次做同类任务时的 p 高于第 t 次。人类专家的 p 是随经验增长的；当前模型的 p 在会话之间是常数（α = 0）。

经验能存放在三个位置，各有不同的 α 与代价：

| 存放位置 | 跨会话 | 改权重 | 容量 | 可审计 / 可回滚 | 能存什么 |
|:---------|:------|:------|:-----|:--------------|:---------|
| 上下文 | 否 | 否 | 受 L 限制，且加剧 p(L) 衰减 | 是 | 任何可被读取的东西 |
| 文件 / 技能（harness 层） | 是 | 否 | 几乎无限 | 是 | **只能存模型能用语言表达出来的东西** |
| 权重 | 是 | 是 | 有限 | 极难 | 包括不可言说的直觉与程序性技能 |

第四篇的 Skill / Memory / Wiki 分层，本质上就是第二行的工程化。它的上限写在最后一列：文件只能存"可被言说的经验"。一个模型做过 1000 次 kernel 优化后形成的"手感"，无法写成 SKILL.md。

### 2.5 一个推论：安全从边界条件变成架构变量

四个方程都是关于"如何让 S(n) 在大 n 上变高"。但 S(n) 是目标无关的——同一个高 S(200) 的模型，既能一天迁移 5000 万行代码，也能自主完成一条 200 步的漏洞利用链。2025 年以前，S(200) 对任何模型都接近零，所以安全问题主要是单条输出的内容问题；2026 年 S(200) 变高，安全问题变成**轨迹级**的问题——不是"这句话能不能说"，而是"这条长链能不能被执行"。

这决定了安全机制的形态必须从 token 级过滤升级为目标级门控，并且门控本身要成为模型系统的一个组件。第七章会展开。

### 2.6 方程组小结

```
可靠性方程   S = ∏ p(L_i)          → p 必须提高一个数量级，且不能随 L 衰减
成本方程     C ≈ n²·ΔL·price_read + Σ t_i·price_gen
                                     → c_i 必须与 L 解耦，t_i 必须可控
校验方程     p' = 1 − (1−p)^k (1−p_v) → 验证器缺失时推理时计算失效，验证必须前移到训练
学习方程     p_{t+1} = p_t + α·Δ     → α 目前为零，经验只能存在文件层
安全推论     S(n) 目标无关           → 门控必须是轨迹级的、架构内的
```

下面五章按方程逐一分析：2026 年各家的具体机制是什么，为什么它们是这个方程的解，以及从方程能推出哪些尚未发生的事。

## 三、校验方程的解：把验证前移到训练——agentic RL 与环境工程

### 3.1 从"环境即数据"推起

校验方程要求验证器在训练时存在。那么训练数据的定义就变了：

```
预训练时代：数据 = 文本
RL 时代：   数据 = (环境, 验证器)
```

一段文本只要存在就能被训练；一个 RL 样本必须同时具备"能交互的环境"和"能判断对错的验证器"，二者缺一不可。这带来两个直接推论：

**推论一：RL 数据的稀缺性由验证器决定，而不由环境决定。** 环境容易造（任何软件系统都是环境），验证器难造（要判断一次操作是否正确）。代码有测试、数学有答案、终端命令有返回值，验证器几乎免费；网页操作、办公任务、创作性工作的验证器昂贵或不存在。**所以能力进步的顺序必然是：代码 → 数学 → 终端 → 浏览器 → 办公 → 创作。** 这不是厂商偏好，是校验方程的结构性结果。2026 年 Terminal-Bench 与 SWE-Bench Pro 的增速远超 OSWorld，办公类 agent 的可靠性明显落后，完全符合这个顺序。

**推论二：验证器本身可以由模型充当，但这引入了新的乘法链。** 用模型做 rubric 评分（Kimi K3 的 Agentic GRM）扩展了验证器的覆盖面，代价是 p_v 不再是 1，且模型验证器可被 reward hacking 攻破。K3 报告在 kernel 优化任务中内置 reward-hacking 检测，正是因为 RL 会找到"让 benchmark 变快但语义不对"的捷径——**验证器的漏洞就是模型学到的漏洞**。

### 3.2 一手材料中的机制：Kimi K3 的后训练流水线

Kimi K3 的 47 页技术报告是 2026 年对 agentic RL 披露最完整的一手资料。它的每个设计都可以对应到方程组的某一项：

```
SFT
 → 3 个领域（编码 / agentic / 通用推理）× 3 个 effort 档位 = 9 个 RL 专家，独立训练
 → MOPD（多教师在线蒸馏）：9 个专家蒸馏回一个统一模型
```

| K3 机制 | 对应的方程与原因 |
|:--------|:---------------|
| 统一白盒 RL 环境可实例化 Claude Code / Codex / OpenClaw / Hermes 等多种 harness，训练时随机切换 | 可靠性方程中的 p 实际上是 p(模型, harness) 的联合函数；只在一种 harness 中训练会让 p 在其他 harness 中掉落。随机化是让 p 对 harness 鲁棒——取 min 而不是取某一个 |
| 超出 effort 预算的轨迹奖励 −1 | 成本方程的 t_i 项直接进入奖励；这是 effort 可控化的训练侧来源 |
| 按 effort 分档训练专家再蒸馏 | 同一预算下的最优策略不同：低预算要"直接给答案"，高预算要"多探索"。分开训再合并，避免策略互相干扰 |
| partial rollout：超长轨迹截断后异步续跑 | n 大时一条百万 token 轨迹会让整批等待（straggler）；这是可靠性方程要求 n 大与训练效率之间的矛盾 |
| 知识图谱采样合成多跳任务 + AET（verify-in-the-loop）过滤 | 合成环境要有验证器——从知识图谱采样保证答案可验证；先让模型试解并验证，过滤掉不可解任务 |
| 个人助理场景用 mock 应用做 rollout，单轨迹数千次工具调用 | 把办公场景（验证器稀缺）转成 mock 环境（状态可检查），人为制造验证器 |
| 1M 上下文 RL 用外置 KV pool | 成本方程在训练侧的体现：长轨迹的 KV 不能放在加速卡上 |
| 逐步 credit assignment（TRCA / TRACE / HiPER 等学术工作同期出现） | n = 200 时只在终点给奖励，每一步分到的信号是 1/200；必须逐步归因，否则梯度被稀释 |

DeepSeek V4 采用 on-policy distillation，OpenAI 披露内部编码推理算力 6 个月增长 100 倍、agentic token 增长 22 倍，都是同一方程的解。Hugging Face 事件后 OpenAI 暂停 RL 训练两周并搁置最大的 RL run——**RL run 已经是与预训练同量级的资源单位**。

### 3.3 一个可验证的推论：同一底座、短期大幅跃迁

如果 2026 年的能力增量主要来自校验方程（训练侧 RL）而不是预训练，那么应该能观察到：**不换预训练底座，agentic 指标在几周到几个月内大幅跃迁。** 事实：

- DeepSeek V4 从 4 月预览到 8 月 0813 版本，Terminal-Bench 2.1 从 72.1 到 87.9（+15.8），DeepSWE 从 12.8 到 62.7，未换底座
- Grok 4.6 官方明确"仅后训练升级"，达到新一代水准
- Anthropic 2 月到 9 月发布 8 个模型，OpenAI 2 月到 9 月发布 5 代——预训练周期不可能支撑这种节奏，只有 RL 的周级迭代可以

**发布节奏压到 6 周级，是校验方程被采纳为主要提升路径的直接后果**，不是营销策略。

### 3.4 对第二篇的修正：推理时计算从"主赛道"降为"原料"

第二篇的判断是"推理时计算是当前最关键的乘数因子，目前未见明确天花板"。校验方程给出了它的天花板：**成本随 n 线性放大，且在验证器缺失时收益坍塌。**

但推理时计算没有消失，而是换了位置——**它成了 RL 的原料**。RL 训练时的 rollout 就是大量的推理时计算（模型在环境里试、思考、验证），训练的目的是把这些昂贵的探索结果压缩进权重，使推理时用更少的 token 达到同样的 p。这解释了 2026 年最重要的一条竞争主轴：

- GPT-5.5 与 5.4 同延迟、token 更少、分数更高
- GPT-5.6 Sol 在 Coding Agent Index 上高于 Fable 5 2.8 分，token 用量少一半
- Opus 4.8 fast mode 便宜 3 倍

"同分少 token"不是效率优化的副产品，而是**推理时计算被摊销进权重的直接证据**。反例是 Gemini 3.8 Flash——输出 token 多 30%、"works harder"——它选择在低价模型上继续用推理时计算换分数，这在成本方程中只对短程任务成立。

## 四、可靠性方程的解（一）：切断乘法链——harness 的第一性原理

### 4.1 为什么 harness 不是"模型的外壳"

如果 p 已经被 RL 推到 99.5%，n = 200 的成功率仍然只有 37%。校验方程在训练时能做的有限，必须在推理时再做一层——但不能用"每步多想几遍"（成本不允许），而要用**结构性手段改变乘法链本身**。

三种结构性手段，恰好对应 harness 最核心的三类组件：

**手段一：分段校验（Verification）。** 把 n 步任务切成 n/m 段，每段结束由一个校验环节（另一个 agent、测试、人类）以概率 v 发现并修复错误。一段的成功率从 p^m 变成 1 − (1 − p^m)(1 − v)，整体：

```
S' = [1 − (1 − p^m)(1 − v)]^(n/m)
```

当 (1 − p)·m 较小时，可以近似为：

```
S' ≈ p^(n·(1−v))
```

**校验器把有效步长从 n 缩短到 n·(1 − v)。** 一个 v = 0.9 的校验器，让 200 步任务在可靠性上等价于 20 步任务。这就是 writer / reviewer、planner / executor 分离模式的数学基础，也是 Opus 4.8"未标记代码缺陷降 4 倍"背后的机制来源。

以 p = 0.99、n = 200 为例：

| 校验有效性 v | 无校验 | m = 5 | m = 10 | m = 20 |
|:------------|:------|:------|:-------|:-------|
| 0（无校验） | 13.4% | 13.4% | 13.4% | 13.4% |
| 0.5 | — | 37% | 37.5% | 38% |
| 0.8 | — | 67% | 68% | 69% |
| 0.9 | — | 82% | 82.5% | 83% |
| 0.95 | — | 90% | 91% | 91% |

注意两点：结果对分段长度 m 几乎不敏感，对 v 极其敏感——**校验器的质量比分段策略重要得多**；校验器本身通常也是模型，它的 v 受同样的 p(L) 约束，所以校验 agent 必须在干净的、短的上下文里工作——这直接导出手段二。

**手段二：上下文隔离（Isolation）。** 第一篇分析 auto 模式坍塌时指出，弱模型留下的错误推理痕迹会污染强模型的后续推理。推广到长程任务：一个子任务中的失败尝试、错误输出、无关文件内容，如果留在主上下文里，会通过 p(L) 衰减拖累后面所有步骤。子 agent 的第一性价值不是并行加速，而是**把子任务的中间状态隔离在独立上下文中，只把结论返回主上下文**——它把 L_i 的增长从"追加所有细节"变成"追加摘要"，ΔL 缩小一个数量级。Claude Code 的 agent teams、GPT-5.6 `ultra` 的默认 4 个并行 agent、dynamic workflows 的数百子 agent，都是这个机制的实例。

**手段三：上下文压缩（Compaction）。** 即使有隔离，主上下文仍随 n 增长。可靠性方程要求 L_i 有界，成本方程也要求 L_i 有界。compaction 在 L 接近阈值时把历史压成摘要，让 L_i 在一个区间内震荡而不是单调增长。**Opus 4.6 把 context compaction 与 1M 上下文同时发布，不是巧合——1M 是让 p(L) 的衰减推迟，compaction 是让 L 不至于用到 1M。** Codex 的跨上下文窗口 notes 是同一机制的另一种实现。

### 4.2 九组件的第一性归约

对 11 个主流 harness 源码的研究（arXiv 2609.00006）归纳出九个组件。用上面的三种手段可以把它们归约为三类功能加一类基础设施：

| 功能类 | 组件 | 作用于方程的哪一项 |
|:------|:-----|:----------------|
| **校验** | lifecycle hooks、permissions、writer/reviewer 模式 | 提供 v，把有效 n 缩短为 n(1−v) |
| **隔离** | sub-agent、session persistence | 缩小 ΔL，切断错误传播 |
| **压缩** | context compaction、dynamic system prompt | 让 L_i 有界，阻止 p(L) 衰减与 n² 成本 |
| **基础设施** | loop engine、tools/skills registry、built-in skills | 不改变方程，提供运行时 |

这个研究还有三个反直觉发现，每一个都能从方程组预测：

- **11 个 harness 无一依赖 LangChain 类通用框架**。第一篇的判断是"编排逻辑从外部框架向模型内部迁移"。当模型的 p 足够高，预定义 DAG 只会限制它；harness 只保留校验 / 隔离 / 压缩这三种模型自己做不了的结构性功能。
- **无一使用向量检索**。第四篇的判断是"LLM 推理替代向量检索"。在方程组里，检索是一次"读入 L"的操作；向量检索返回低信噪比 chunk 会推高 L 却不提高 p，而让模型用 `ls` + `grep` 精确取用则 ΔL 最小。
- **Skills 采用率（9/11）高于 MCP（8/11）**。第三篇的判断。Skill 是"渐进披露"——只在需要时加载指令，ΔL 按需；MCP 把所有工具 schema 前置到上下文，ΔL 固定支出。

### 4.3 模型-harness 共演化：p 是联合函数

一个更深的结论：**p 不是模型的属性，而是 (模型, harness) 对的属性。** 同一个模型在不同的工具签名、提示模板、compaction 策略下，p 可以差出足以让 S(200) 从可用变为不可用的幅度。

这个事实在 2026 年产生了两条相反方向的解：

- **Cursor Composer 2**：基于 Kimi K2.5 继续预训练，然后**在真实 Cursor harness 中做 RL**。把 harness 固定为训练分布的一部分，让 p(模型, Cursor) 最大化。代价是换 harness 会掉分。
- **Kimi K3**：在训练环境中**随机切换 harness**。让 p 对 harness 的 min 最大化。代价是在任一 harness 上不如专门训练的模型。

两者都承认同一件事：**harness 已经不是模型的外壳，而是训练的一部分。** 这是 2026 年最容易被低估的结构变化——它意味着"换 harness"在未来的成本更接近"换模型"，harness 的接口稳定性会像指令集一样重要。

### 4.4 编排权交给模型：第一篇预测的兑现与修正

Opus 4.8 的 dynamic workflows 让模型自己写 JavaScript 编排脚本调度子 agent；OpenAI 的 Programmatic Tool Calling 让模型用代码批量调用工具。**编排逻辑从 harness 硬编码变成模型生成的代码**——第一篇第三章预测的"编排从外部框架向模型内部迁移"在半年内兑现。

但要做一个修正。第一篇预测 harness 会"越来越薄，退化为安全护栏 + 审计日志 + 资源管控"。2026 年的证据显示：**业务编排确实迁入了模型，但校验 / 隔离 / 压缩这三种结构性功能没有变薄，反而变厚了**——因为它们不是在替模型做决策，而是在改变乘法链的结构，这是模型自己在单一上下文中做不到的。更准确的表述是：

> harness 的"决策部分"迁入模型，harness 的"结构部分"迁入训练环境成为模型被训练的契约。剩下的 harness 是一个运行时，它的形态会像操作系统内核一样稳定下来。

DeepSeek Harness v0.1 的设计——Cordis 微内核、"everything is a plugin"、唯一被单独打包的 `@deepseek-ai/dsh-agent-loop`、可把 Claude Code / Codex 作为子 agent 驾驭——正是"harness 内核化"的第一个明确形态。协议层（MCP 归入 Linux Foundation、Agent Skills、SEP-2640 让技能通过 MCP 分发、ACP）则是内核之上的系统调用接口。

## 五、成本方程的解：让每一步的成本与历史长度解耦——架构的第一性原理

### 5.1 成本方程对架构提出的四个要求

回到 C ≈ price_read·(n·L_0 + n²·ΔL/2) + price_gen·Σt_i。要让 n = 200 经济可行，架构必须做到：

1. **注意力的每 token 计算量不随 L 线性增长**（否则 n² 项的系数不可承受）
2. **KV cache 的内存不随 L 线性增长**（否则 1M 上下文的并发服务不可能）
3. **每 token 的激活计算量尽量小**（决定 price_gen 与 price_read 的底）
4. **知识容量的增长不推高每 token 计算量**（否则"更博学"与"更便宜"矛盾）

2026 年国产开源模型的技术报告，恰好是对这四个要求的逐条回答。闭源模型几乎不披露架构，但它们的定价行为（Opus 4.6 的 1M 以 beta 加价形式推出，说明成本结构不同于 200K）暗示走了类似路线。

### 5.2 要求一与二：注意力的三条路线

| 路线 | 代表 | 机制 | 在方程中的效果 | 取舍 |
|:-----|:-----|:-----|:-------------|:-----|
| **压缩 + 稀疏选择** | DeepSeek V4（CSA / HCA） | CSA：KV 做 4 倍压缩，用 FP4 精度的 lightning indexer 对压缩块打分取 top-k；HCA：128 倍重度压缩覆盖全局。61 层中前 2 层 HCA，其余 CSA/HCA 交替；MTP 块用滑窗 | KV cache 降至约 2%；每 token 只对 top-k 块计算注意力 | 保留精确检索，代价是索引器的额外计算与训练复杂度 |
| **线性化 + 少量全注意力** | Kimi K3（KDA + Gated MLA） | 3 层 KDA（Kimi Delta Attention，线性注意力，解码状态 O(1)）配 1 层 Gated MLA（NoPE）。KDA 用下界衰减 g_min = −5 让对角 tile 全部可用 Tensor Core，输出门全秩 | 3/4 的层每 token 成本与 L 无关；1/4 的层保证精确召回 | 3:1 是效率与召回的折中，比例本身是超参 |
| **块稀疏** | MiniMax M3（MSA） | 每 query 只对 top-16 个 128-token 块做注意力 | 1M 上下文单 token 注意力计算降至 1/20 | 实现最简单、硬件友好；精确性取决于块选择器 |

三条路线的共同结构是：**全注意力只保留在少数层或少数块，其余用压缩、线性化或稀疏替代。** 这个结构可以直接从方程推出——全注意力是唯一能保证精确召回的机制，但成本 ∝ L；所以它必须存在、又必须被限制在最小必要范围内。

### 5.3 要求三：把激活参数压到 6B–100B

MoE 把"总参数"与"激活参数"解耦。2026 年的变化是稀疏度的极端化：

- Kimi K3：896 个专家激活 16 个，稀疏度 56（Stable LatentMoE：先投影到低维 latent 再路由，配 SiTU-GLU 激活与 Quantile Balancing 负载均衡，解决高稀疏度下的训练不稳定）
- DeepSeek V4-Pro：1.6T 总 / 49B 激活，稀疏度约 33
- Qwen3.8-Flash-Next：125B 主干仅激活 6B

**总参数继续向 5T–10T 增长，激活参数收敛在 6B–100B 区间。** 这是为什么 2.8T 的 K3 只需 64 张加速卡即可服务。price_gen 的下限由激活参数决定，与总参数无关。

配套的是数值精度与优化器：DeepSeek V4 与 K3 都用 FP4 / MXFP4 量化感知训练，推理直接以 4 位权重服务；都用 Muon 优化器（DeepSeek 首次在 1.6T 规模验证）。FP4 让每个参数搬运的字节数减半——在成本方程里这是 price_read 与 price_gen 的共同系数。

### 5.4 要求四：把"知道"从"计算"中剥离——Engram

这是 2026 年国产架构最重要的原创贡献，也是第四篇判断的架构层验证。

Transformer 用注意力和 MLP 同时承担"推理"和"记忆"。但很多记忆不需要计算——某个 N-gram 后面通常接什么，是查表问题。Engram 引入条件记忆模块：对当前 N-gram 做哈希，O(1) 查出一个向量与隐状态融合。**记忆从 FLOPs 搬到了内存**，而内存比算力便宜得多，且记忆表可以放在主机内存并预取，不占显存。

论文最重要的发现是 **MoE 参数与记忆参数之间存在 U 型 scaling law**——给定总参数预算，两者按一定比例配置最优，全投 MoE 或全投记忆都次优。27B 验证：MMLU +3.4、BBH +5.0、NIAH 84.2 → 97.0。

Qwen3.8-Flash-Next 的配置是这条路线的第二次大规模验证："125B 主干激活 6B + 51B N-gram 嵌入表 + 4B MTP"，训练成本为 Qwen3.7-Plus 的 1/9。**知识容量增长了，每 token 计算没有增长**——这正是要求四。

在方程组里，Engram 还有一个更深的意义：它是"记忆"作为一个**独立可寻址的参数块**首次出现在主流架构中。第六章会说明，这为学习方程的突破留下了架构接口。

### 5.5 深度：让 100+ 层可训练

总参数增长除了靠宽度（MoE），也靠深度。深网络的障碍是残差信号的数值不稳定。两个 2026 年的解：

- **mHC（DeepSeek）**：Hyper-Connections 用可学习的混合矩阵替代残差连接，但深网络中会发散。mHC 把混合矩阵约束到 Birkhoff 多面体（双随机矩阵），用 Sinkhorn-Knopp 迭代投影，保证谱范数 ≤ 1。V4 使用 hc_mult = 4。
- **Attention Residuals（Kimi K3）**：每层不只看上一层，而是对之前所有块的输出做注意力加权（Block AttnRes，每 8 层一块）——"跨深度的注意力"。

两者本质相同：**残差连接从固定的恒等映射变成可学习、有约束的信息路由。**

### 5.6 effort：成本方程与校验方程的耦合点

effort 参数是 2026 年 API 层最一致的变化：Opus 4.6 四档、4.7 加 xhigh、DeepSeek V4-Pro-0813 三档、Grok 4.6 xhigh、Fable 5.1 逐消息 effort。在方程组里它的位置很清楚：**effort 控制 t_i（成本方程），而 t_i 又决定推理时能做多少探索与检查（校验方程）。** 它是两个方程唯一的公共变量，因此成为调用方最重要的控制旋钮。

而 K3 的"超预算奖励 −1"说明：effort 不是简单截断思维链，而是模型在训练时学会了在不同预算下采用不同策略。adaptive thinking（Opus 4.6）则把"要不要深想"的判断交回模型——这需要训练时有难度感知的奖励，本质上是让模型自己估计当前步的 p 与所需 t_i 的关系。

### 5.7 从成本方程看 Gartner 的"推理悖论"

Gartner 8 月的判断：token 单价到 2030 年降 95%，但 agentic 工作流的推理总成本到 2028 年涨 5 倍以上。在成本方程里这不是悖论：price 下降是线性的，n² 项的增长是二次的。只要 n 继续增长（它一定会——这是能力进步的定义），总成本就会上升。**成本核算单位从"每百万 token"变成"每任务完成"，是成本方程的直接推论**，也是"tokenizer 税"、缓存定价、effort 档位这些隐性变量为什么突然重要的原因。

## 六、学习方程的解：α 为什么仍然是零，以及它会从哪里变成正数

### 6.1 2026 年所有"自进化"都在文件层

按 2.4 节的三个存放位置检视 2026 年的"记忆"与"自进化"：

| 系统 | 机制 | 存放位置 | α 的来源 |
|:-----|:-----|:--------|:--------|
| Fable 5 的 Slay the Spire 实验 | agent 把经验写入文件，下次读取；增益 3 倍 | 文件 | 可言说的经验（"这张牌在这个局面下不要打"） |
| Codex 跨上下文窗口 notes | 上下文耗尽前写 notes，新窗口读取 | 文件 | 会话内的状态延续 |
| Hermes Agent（130k+ stars） | 把重复成功的操作序列自动沉淀为 SKILL.md；四层记忆 | 文件 | 可言说的流程 |
| hermes-agent-self-evolution | 用 DSPy + GEPA 离线演化提示与技能 | 文件 | 离线搜索，不改权重 |
| Continual Harness（arXiv 2605.09998） | agent 对自身 harness 做 reset-free 的 CRUD；可联合 PRM / DAgger soft SFT 训练 | 文件为主，联合训练时触及权重 | 最接近权重层的尝试 |
| `doubao-seed-evolving` | 固定 model ID，权重按周替换为最新版本（当前 = Seed 2.1 Pro） | 权重，但由厂商离线替换 | **不是在线学习**，是滚动发布 |

结论：**2026 年没有一个生产系统在权重层做在线学习。** 所有"越用越好"都是第四篇 Memory / Skill 层的实例。这不是行业保守，而是理性选择——权重层学习面对三个未解问题：灾难性遗忘（新经验覆盖旧能力）、安全（用户交互可以直接改变模型行为，等于开放式的投毒通道）、不可审计（改了什么、能否回滚）。文件层在这三点上都有现成答案。

### 6.2 文件层的天花板

但 2.4 节的最后一列写着文件层的上限：**只能存模型能用语言表达的经验。** 可言说的经验（"这个 API 要先 auth"、"用户偏好中文"）占日常任务改进的大部分，所以文件层的收益在 2026 年显得很高。但下面这些东西写不进 SKILL.md：

- 做过上千次后形成的、比"规则"更细的判断直觉
- 在陌生环境中快速找到规律的能力本身
- 对某个代码库风格的整体感知

ARC-AGI-3 正是为测量最后一项设计的：交互式环境、规则未知、必须在会话内通过试错学会。6 月 30 日的结果，Opus 4.8 总分 1.5%，OpenClaw + Opus 4.7 组合 5.2%——文件记忆帮不上忙，因为每个环境都是新的。

### 6.3 α 会从哪里变成正数

从方程组推，有三条路径，难度递增：

**路径一：用 RL 教模型"如何在会话内学习"（α 在上下文层）。** 这是把学习方程折叠进校验方程——在训练时给模型大量"规则未知、需要试错"的环境，让它学会元策略。GPT-6 Astra 在 ARC-AGI-3 上"96% 关卡达到人类效率"（口径与 6 月的总分不同，需打折看）如果属实，说明这条路已经走通了一段。它不改权重、不跨会话，但让 α 在会话内为正。

**路径二：把记忆做成可写的参数块（α 在架构层）。** Engram 已经证明记忆可以是一个独立寻址的参数模块；把它从"训练时写入"变成"推理时可写入"，就得到一个不触碰主干权重、可审计、可回滚的权重层记忆。Nested Learning / Hope / Titans 这一系研究在做同样的事。这是最有可能在 12–24 个月内出现的架构突破。

**路径三：有约束的在线权重更新（α 在主干权重）。** 需要同时解决遗忘、安全、审计。Continual Harness 的联合训练是早期形态。生产可用还需要更长时间。

**判断：下一个真正的代际不会由更高的 benchmark 分数定义，而由 α > 0 定义——第一个在陌生任务上第 10 次明显好于第 1 次的模型。**

## 七、安全推论的解：从内容过滤到轨迹门控

### 7.1 为什么 2026 年的安全事件形态完全不同

2.5 节推导过：S(200) 变高后，危害能力从"说错话"变成"做成事"。2026 年的四个事件都是这个转变的表现：

**Mythos Preview 不公开发布（4 月）。** 它在所有主流操作系统和浏览器中发现零日漏洞，Firefox 漏洞利用 181 次（Opus 4.6 为 2 次），找出 27 年历史的 OpenBSD bug。Anthropic 选择通过 Project Glasswing 仅向 40+ 机构开放。这是**第一次因 S(n) 过高而不发布**。

**GPT-6 Astra 被评为 Preparedness 框架 Critical 级网络风险（9 月）。** ExploitBench 100%。同时 OpenAI 承认其推理链更难监控——校验方程的另一面：当模型把"检查"内化进权重，外部就更难看到它在想什么。

**Fable 5 的分类器回退架构（6 月）。** 分类器识别高风险请求，命中即回退到 Opus 4.8，>95% 会话无回退。**一个"模型"实际上是一个模型对加一个分类器的系统。** 这是轨迹级门控的第一个生产形态——门控作用于目标而不是 token。

**Hugging Face 事件（7 月）。** 攻击者利用内部模型与 GPT-5.6 Sol 生成的数据集投毒，取得训练节点权限、窃取凭证。OpenAI 暂停 RL 训练两周、搁置最大的 RL run。**如果数据 = (环境, 验证器)，那么投毒环境就是新的攻击面。** 训练流水线安全从此成为独立学科。

### 7.2 一个由校验方程推出的不对称：发现远快于修复

Glasswing 至 9 月累计发现 26,000+ 漏洞，修复率 <1%。这个不对称可以从 3.1 节的推论一直接推出：**发现漏洞是一个验证器廉价的任务**（崩溃、越权、利用成功都是清晰信号），**修复漏洞是一个验证器昂贵的任务**（要理解原意、不引入回归、通过全部测试）。按"能力进步顺序由验证器可获得性决定"，发现能力必然领先修复能力。这个缺口是系统性风险，也是最明确的产品空白。

### 7.3 harness 层的供应链问题

技能是可执行代码，技能市场就是软件供应链。OpenClaw 累计 169 条安全通告；ClawHavoc 事件涉及 341–1467 个恶意 skills；135k 实例暴露公网；Claw Chain 漏洞 CVSS 9.6。prompt-injection 竞技场显示模型间差异巨大（Opus 4.5 攻击成功率 0.5% vs Gemini 2.5 Pro 8.5%）。第四章说 harness 内核化、协议接口化——那么 Skills 规范加入签名、沙箱、权限声明就是必然的下一步。

**国产路线的"效率优先"是约束条件的产物。** 算力受限意味着成本方程的系数更紧，所以国产模型在要求一至四上走得最激进（KV 2%、稀疏度 56、FP4、Engram）。同时因为开源需要发技术报告，它们成为理解这一代架构的唯一一手来源——**披露度反转**：闭源不再披露架构，闭源机制只能靠开源报告反推。

**开源与闭源的差距稳定在 3–6 个月，不是偶然值。** 校验方程的解（RL 环境 + 验证器）可以被复制，但需要时间搭环境；成本方程的解（架构）在开源报告发布后可被吸收。3–6 个月大约是"看到闭源效果 → 猜出机制 → 搭环境 → 训完"的周期。差距不会收敛到零（RL 算力是硬约束），也不会扩大到一年以上（机制会泄露）。但要注意能力门控带来的隐藏差距：最强模型（Mythos、Astra）公开滞后，公开 benchmark 显示的差距比真实差距小。

## 九、趋势与断言：从方程推出的、可证伪的判断

以下断言每一条都附带"证伪条件"。如果证伪条件出现，说明方程组需要修正，而不是断言需要辩护。

### 断言一：能力进步的顺序由验证器的可获得性决定

代码 → 数学 → 终端 → 浏览器 → 办公 → 创作。未来 12 个月，办公类 agent 的可靠性提升将主要来自"把办公系统 mock 成可验证环境"，而不是模型本身；办公 Agent 大战的胜者是连接器与验证器最多的那家，不是模型最强的那家。
**证伪条件**：某个验证器稀缺的领域（如开放式写作）出现与代码同速的可靠性提升。

### 断言二：推理时计算持续被摊销进权重，"同分少 token"是长期趋势

同一任务、同一分数下的 token 消耗每半年下降 30%–50%。effort 档位的作用会从"控制质量"转向"控制成本上限"，因为默认档位的质量会越来越够用。
**证伪条件**：主流模型在固定分数下的 token 消耗停止下降，或厂商普遍转向 Gemini 3.8 Flash 式的"多 token 换分"。

### 断言三：harness 内核化，业务编排彻底迁入模型

校验 / 隔离 / 压缩三种功能会稳定为 harness 内核，接口通过 Skills / MCP / ACP 标准化；模型生成的编排脚本取代所有硬编码 workflow；"harness 驾驭 harness"成为常态。LangChain 类通用框架不会回归。
**证伪条件**：主流 harness 重新引入预定义 DAG 编排，或向量检索回到 harness 核心路径。

### 断言四："上下文长度"作为指标死亡，被 p(L) 斜率与 c(L) 斜率取代

1M 上下文的定价将在 12 个月内与 200K 趋同；10M 上下文会出现在开源模型中但不会被当作卖点；真正的竞争指标是长上下文质量的衰减速度与每 token 成本的增长速度。
**证伪条件**：厂商继续对长上下文收取显著附加费，或 1M MRCR 类指标出现新的断层。

### 断言五：下一个代际由 α > 0 定义，路径是可写的 Engram

12–24 个月内出现第一个生产级的"可在推理时写入的参数化记忆"，它不触碰主干权重、可审计、可回滚；ARC-AGI-3 总分突破 30% 是这条路径打通的信号。在此之前，所有"自进化 agent"都停留在文件层，其收益有可言说性的天花板。
**证伪条件**：ARC-AGI-3 在 24 个月内仍停留在 10% 以下，或权重层记忆方案出现严重的遗忘 / 安全事故导致行业回退到纯文件层。

### 断言六：能力门控成为模型分层的一部分，"最强模型不公开"常态化

最强模型先服务防御方、公开版本滞后 3–6 个月；双模型加分类器架构普及到所有前沿发布；API 将暴露回退率或路由信息。漏洞发现与修复的缺口催生专门的修复 agent 市场。
**证伪条件**：前沿实验室恢复"最强模型直接公开"的做法，或分类器门控被证明可以被单一模型的内化对齐完全替代。

### 断言七：开源 - 闭源差距稳定在 3–6 个月，国产效率架构反向输出

Engram、mHC、混合注意力、FP4 + Muon 会被闭源厂商吸收（大概率已在发生）；国产最强版本闭源、次强版本开源成为标准策略；差距既不收敛也不扩大。
**证伪条件**：差距在两个连续代际内扩大到 12 个月以上（说明 RL 算力壁垒比方程预期更硬），或收敛到 1 个月以内（说明 RL 环境比预期更容易复制）。

### 断言八：成本核算单位变为"每任务"，缓存价格成为主变量

24 个月内主流厂商推出按任务或按结果计费；推理引擎的竞争焦点转向 KV cache 持久化与跨请求复用；企业选型的首要指标变为"完成代表性任务集的总费用 × 成功率"。
**证伪条件**：token 标价重新成为唯一定价维度，或 n 的增长停滞使 n² 项失去主导地位。

## 十、对前四篇判断的继承与修正

一个第一性原理的框架必须能回头检验自己。下表列出前四篇的核心判断在 2026 年证据面前的状态：

| 篇 | 原判断 | 2026 年证据 | 状态 |
|:---|:------|:-----------|:-----|
| 01 | 乘法衰减定律 p^n | n 从 20 到 200，H > 200 需 p > 99.65% 得到独立验证 | **继承并深化**：p 需修正为 p(L)，随上下文长度衰减 |
| 01 | Agent 能力由最弱一项决定（短板效应） | harness 随机化训练、writer/reviewer 分离都是在补最弱项 | 继承 |
| 01 | 编排逻辑从外部框架向模型内部迁移 | dynamic workflows、Programmatic Tool Calling、11 个 harness 无通用框架 | **兑现**，但需修正：决策部分迁入模型，结构部分（校验/隔离/压缩）迁入训练契约，harness 内核化而非消失 |
| 01 | 模型能力商品化速度快于预期 | 中档模型（Sonnet 5）超过前代旗舰；开源差距 3–6 个月 | 部分兑现；**修正**：能力门控让最强模型的真实差距大于公开差距 |
| 01 | 评测能力是最稀缺资源 | METR 时间地平线 >16 小时已无法可靠测量；benchmark 两三分差异对应长程任务的巨大差距 | **强化** |
| 02 | 推理时计算是最关键乘数因子，未见天花板 | 成本随 n 线性放大、验证器缺失时收益坍塌 | **修正**：天花板在成本方程；推理时计算降为 RL 的原料，被摊销进权重 |
| 02 | 精调是"最后一公里"工具，护城河贬值 | 精调确实边缘化；但 Composer 2 在自家 harness 中 RL | **修正**：精调消亡，但"在自己的环境中做 RL"成为新的定制形态——喂环境而非喂数据 |
| 02 | PRM 是最值得关注的方向 | 逐步 credit assignment、Agentic GRM 成为长程 RL 核心 | 兑现 |
| 03 | Skill 的渐进披露优于 MCP 的前置 schema | 9/11 harness 采用 Skills，高于 MCP 8/11；SEP-2640 让 Skills 通过 MCP 分发 | 兑现 |
| 04 | LLM 推理替代向量检索 | 11 个 harness 无一使用向量检索 | **兑现** |
| 04 | 知识供给从"查询时"走向"编译时"，模型原生知识体系是终局 | Engram 把记忆做成独立参数块；Qwen3.8 用 51B 记忆表 | **在架构层得到验证**：知识正从上下文注入下沉到参数化外置记忆 |
| 04 | Memory 是隐性知识显性化的通道 | Fable 5 文件记忆、Hermes 技能沉淀是主流"自进化"形态 | 兑现；**补充**：文件层有可言说性天花板，下一步是可写的参数记忆 |

四篇的核心框架全部经受住了检验，需要修正的是三处：p 不是常数而是 p(L)；推理时计算有成本天花板并正被摊销进权重；harness 不是变薄而是内核化。这三处修正恰好就是本文四个方程中新增的部分。

## 十一、架构师的行动含义

### 11.1 用方程组读新闻

每一条发布公告，先问它作用于哪个变量，再问是否改变主线：

```
它提高了 p？                → 看是否换了预训练底座；没换就是 RL，关注环境/验证器披露
它改变了 p(L) 的斜率？        → 看长上下文质量指标随长度的曲线，不看窗口大小
它降低了 c_i 对 L 的依赖？    → 看 KV 占比、激活参数、1M 是否与 200K 同价
它控制了 t_i？              → 看 effort 档位设计与"同分少 token"的数据
它提供了 v / 隔离 / 压缩？    → 这是 harness 层，看它是否被写进训练环境
它让 α > 0？                → 问：改不改权重？跨不跨会话？存的是可言说的还是不可言说的？
它是门控？                  → 看分类器/回退/分级发布，判断隐藏差距
```

不落在任何变量上的发布（用户量、融资、命名），不改变技术判断。

### 11.2 选型与建设

**模型选型用任务级总成本。** 自建 10–20 个真实工作流的代表性任务集，在相同 harness 下记录成功率、耗时、总 token 费用。tokenizer 差异、effort 设置、缓存命中率对成本的影响常大于标价差异。

**harness 选型看两点：能否导出轨迹、是否遵循协议。** 能导出轨迹意味着你在积累未来的 RL 环境与评测集；遵循 Skills / MCP / ACP 意味着可以被其他 harness 驾驭。不把业务逻辑写进任何一家 harness 的私有插件系统。

**私域投入优先建"环境"而非"数据"。** 承接第四篇：把企业系统 mock 成带验证器的可交互环境，它同时是评测集、未来 RL 环境、agent 测试床。断言一说明这是办公类 agent 可靠性的唯一杠杆。

**记忆层用文件 + 技能沉淀，为参数记忆预留接口。** Hermes / Continual Harness 类方案可落地；设计上要能审计、回滚技能（它们是可执行代码）；预留将高频文件记忆迁入参数记忆的通道。

**安全预设两道线。** 对接前沿模型时预期回退与拒答，容忍"同一请求不同子模型响应"的一致性问题；对技能与插件按软件供应链管理——签名、沙箱、最小权限。

**规划节奏按每季度一个能力台阶。** 校验方程决定了 RL 迭代是周级的，6 周节奏不会放缓。把能力假设参数化（上下文、effort、并行度），让系统在下一代到来时只改配置。

### 11.3 主动感知的信号清单

| 优先级 | 信号 | 对应变量 | 判读 |
|:------|:-----|:--------|:-----|

## 十二、收尾：从考试到上班

第二篇用了一个类比：训练时计算是"考前多学习"，推理时计算是"考试时多检查"。2026 年发生的事，可以用这个类比的延伸来概括——**模型从"考试"进入了"上班"**。

上班和考试有五个根本区别，恰好对应本文的五个方程：

- 上班没有标准答案卡。每个决定当场没人告诉你对不对，所以"检查"必须在入职前练成习惯——这是校验方程，验证前移到训练。
- 上班一天要做两百个决定，而不是二十道题。任何一个决定的失误率都必须低一个数量级，并且不能因为下午累了就下降——这是可靠性方程，p 必须高且不随 L 衰减。
- 老板算的是工资和产出，不是你想了多久。想得久但产出一样的人，会被想得快的人替代——这是成本方程，同分少 token。
- 好员工第二年比第一年强。当前的模型每天早上都是第一天上班，只是桌上留了一本前任写的笔记——这是学习方程，α 仍为零，记忆在文件层。
- 能做成事的人需要权限管理。能一天迁移五千万行代码的人，也能一天做成别的事——这是安全推论，门控必须是轨迹级的。

用这个类比重看 2026 年：Opus 4.6 是第一个真正能"上班一天"的模型；agentic RL 是把"检查"练成习惯的入职培训；harness 是办公室的流程制度——分工、复核、归档；稀疏注意力与 Engram 是让这个员工的时薪降到可承受；文件记忆是那本桌上的笔记；Mythos 不发布，是因为发现了这个员工能做的事超出了任何岗位描述。

而未来最重要的那一步，是让员工第二年真的比第一年强。

> 2026 年的变化不是模型"更聪明了"，而是行业在乘法衰减定律的约束下，找到了让数百步任务在可靠性、成本、安全三个维度同时成立的一组解。理解这组解的方程，就不再需要被动跟进每一次发布——因为下一次发布必然仍然落在这组方程里，直到学习方程被真正解开，那才是下一个方程组的开始。
