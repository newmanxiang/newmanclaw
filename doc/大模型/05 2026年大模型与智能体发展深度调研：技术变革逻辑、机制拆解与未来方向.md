# 2026 年大模型与智能体发展深度调研：技术变革逻辑、机制拆解与未来方向

作者：向春（架构师）
日期：2026-09-10
背景：作为系列第五篇，本文试图回答一个比“最近发布了哪些模型”更重要的问题：从 Opus 4.6、Kimi K3、DeepSeek V4 到各种智能体 harness，表面效果快速提升的背后，究竟发生了什么结构性变化？本文不把“第一性原理”理解为给观点套上公式，而是先定义智能体真正优化的对象、约束与系统边界，再区分事实、机制推断和趋势假说。核心判断是：**2026 年最根本的变化，不是模型变得更大，而是行业的优化对象从“单次模型响应”转向“在环境中完成目标的完整轨迹”**。后训练、架构、harness、记忆和安全的变化，都是围绕轨迹效用展开的不同工程干预，而不是某个公式的唯一解。

---

## 〇、先给结论：变化的是优化对象，不是某一个技术点

如果把 2026 年的新闻逐条排列，会得到一张热闹但很难使用的时间线：

- Opus 4.6 推出 1M 上下文、adaptive thinking、context compaction 和 agent teams
- DeepSeek V4 用稀疏注意力、mHC、FP4 QAT 和极低 KV cache 支撑长上下文
- Kimi K3 披露多领域、多 effort 的 RL 专家、百万 token rollout 和多 harness 训练环境
- Claude Code、Codex、Cursor、DeepSeek Harness 都在增强子 agent、压缩、持久化和动态编排
- Fable 5、GPT-6 Astra 将能力门控和分级发布带入产品架构

这些事件并不天然属于同一条技术路线。把它们串起来的，不是“参数更大”“推理更久”或“harness 更复杂”，而是评价标准发生了变化：

```
过去：给定输入 x，模型能否生成高质量输出 y
现在：给定目标 g 和环境 E，系统能否以可接受的成本与风险完成一条有效轨迹 τ
```

这里的“系统”不只是模型，而是：

```
智能体系统 = 模型策略 × Harness × 工具 × 环境 × 记忆 × 权限机制
```

因此本文的核心结论不是“agentic RL 是唯一解”，也不是“harness 将取代模型”，而是六个层次不同、证据强度不同的判断：

1. **高置信事实：优化与评测正从单轮输出迁移到多步轨迹。** Terminal-Bench、SWE-Bench Pro、OSWorld、BrowseComp 等评测，衡量的已经不是一道题，而是模型在环境中的持续行动。
2. **高置信判断：模型能力越来越是模型与 harness 的联合属性。** 工具定义、上下文压缩、子 agent 隔离和运行时验证都会显著改变结果。
3. **中高置信判断：带可验证反馈的环境，正在成为后训练扩展的重要瓶颈。** 但它不是唯一瓶颈，也不能解释所有领域的能力进步。
4. **高置信判断：架构竞争的共同目标是降低“完成一条有效轨迹”的成本。** 稀疏注意力、MoE、FP4、缓存和 effort 分档分别作用于不同成本项，不能简单归为同一机制。
5. **高置信事实：当前生产级“自进化”主要发生在外部状态层，而不是在线权重更新。** 文件记忆、Skill 和会话持久化让系统跨会话改善，但不等于模型权重持续学习。
6. **中高置信判断：自主性与治理能力必须共同增长。** 能完成更长轨迹的系统同时扩大了误操作、越权和供应链风险，因此权限、沙箱和轨迹监控会成为 harness 的长期组成部分。

以上六条不是终局答案。它们是目前最能解释多源证据、同时允许反例存在的一组工作假说。

## 一、从第一篇的乘法衰减定律重新出发：保留直觉，修正模型

### 1.1 `p^n` 捕捉了什么

第一篇提出：

```
S = p^n
```

它捕捉了一个非常重要的直觉：**当一个任务依赖多个必要环节时，局部错误会在长链条中累积，任务级成功率下降得比单点 benchmark 更快。**

在“n 个步骤相互独立、难度相同、每步都必须成功、错误不可恢复”的理想条件下，这个公式成立。反解 `p = S^(1/n)` 可以看到：若希望一个 200 步任务有 50% 的全链成功率，每个步骤的成功率需要约 99.65%。这解释了为什么模型在简单问答中“只差一点”，进入复杂 Agent 场景后体感可能差很多。

但必须明确：**`p^n` 是一个揭示风险的基准模型，不是普遍定律。**

真实智能体不满足它的全部假设：

- 步骤难度不同，成功概率不是同一个 p
- 错误往往相关，一个错误假设可能同时污染后续多步
- 有些失败可以重试、回滚或被测试发现
- 有些工具调用不是关键步骤，失败不会导致整体失败
- 任务可能并行执行，工具调用数不等于串行关键路径长度
- 成功不是二元变量，很多任务允许部分完成

更一般的表达是条件概率链：

```
P(所有关键条件成立)
= ∏ P(第 i 个关键条件成立 | 当前状态与前序历史)
```

这仍然是乘法，但每一项都取决于状态、任务难度、工具、历史错误和恢复机制。它无法直接推出“某一种技术是唯一解”，却能告诉我们真正该观察什么：

1. 串行关键路径有多长，而不是一共调用了多少次工具
2. 每一步的错误是否相关
3. 错误能否被观察、检测、回滚
4. 一个错误的影响半径有多大

### 1.2 2026 年真正变化的是“可处理轨迹的长度与开放性”

2026 年任务形态出现了明显变化：

- Stripe 披露 Fable 5 在一天内完成 5000 万行 Ruby 迁移
- Kimi K3 报告中的单条 RL rollout 可达数千次工具调用、百万 token
- Opus 4.8 的 dynamic workflows 可动态调度数十至数百个子 agent
- OSWorld、Terminal-Bench 等基准将模型置于可交互环境中持续执行

这些数字不能直接换算成 `n`：5000 万行代码不等于 5000 万个串行认知步骤，数千次工具调用中也可能包含查询、重试与并行分支。它们可靠地说明的只有一点：**前沿系统正在处理更长、更开放、更依赖环境反馈的轨迹。**

长轨迹放大了四类过去不突出的约束：

- 错误累积与恢复
- 状态持续增长
- 计算与延迟成本
- 行为权限与风险

这四类约束，而不是 `p^n` 本身，才是理解 2026 年技术变化的入口。

## 二、最小分析模型：智能体是一个受约束的序贯决策系统

### 2.1 先定义优化对象

设智能体在环境中形成一条轨迹：

```
τ = (o₀, a₀, r₀, o₁, a₁, r₁, …, o_T)
```

- `o_t`：第 t 步能看到的观察，包括用户目标、文件、工具返回和历史摘要
- `a_t`：模型与 harness 共同决定的行动
- `r_t`：环境反馈，不一定是数值奖励，也可能是测试结果、错误信息或用户纠正
- `T`：轨迹长度

系统真正要优化的不是某一步答得漂不漂亮，而是：

```
最大化 E[U(τ)]

约束：
C(τ) ≤ 成本预算
L(τ) ≤ 延迟预算
R(τ) ≤ 风险阈值
```

`U(τ)` 是最终任务效用；`C(τ)` 是模型、工具、基础设施与人工成本；`L(τ)` 是完成时间；`R(τ)` 是误操作、越权和安全风险。

这不是一个可以直接计算答案的“万能方程”，而是一个最小抽象。它的价值是避免把目标与手段混在一起：

- Agentic RL、SFT、蒸馏是改变策略的手段
- Context compaction、子 agent 是改变观察和状态管理的手段
- 稀疏注意力、MoE、缓存是改变成本的手段
- 测试、critic、人工审批是改变错误检测和恢复的手段
- 沙箱、权限和分类器是改变风险的手段

不同场景可以选择不同组合。没有一个手段从这个模型中被“唯一推出”。

### 2.2 决定轨迹效用的六个底层变量

#### 变量一：策略质量——每一步是否做出合适行动

它包括理解目标、规划、选工具、构造参数、判断终止等能力。预训练、后训练和推理时计算都会影响它。

#### 变量二：可观测性——系统是否看到了足够且相关的状态

上下文长度只定义“最多能装多少”，不定义“看到的信息是否相关”。更准确的关系是：

```
行动质量 = f(
  模型能力,
  有效信息量,
  噪声比例,
  信息位置,
  历史错误,
  状态压缩损失,
  工具与 Harness
)
```

因此不能假定可靠性是上下文长度的单调减函数。上下文变长可能增加噪声，也可能补充关键证据。真正重要的是**有效信息密度和状态保真度**。

#### 变量三：可评价性——行动结果能否被判断

代码有测试，数学有答案，终端命令有返回值；开放式办公任务和创作任务往往没有廉价、准确的判断标准。验证器越明确，越容易生成训练信号，也越容易在运行时恢复。

但“验证器可得性”只是能力进步速度的一个变量。数据规模、商业投入、环境成熟度、隐私约束和任务容错率同样重要。

#### 变量四：可恢复性——错误能否被发现并修复

发现错误与修复错误必须分开：

```
恢复概率
= P(检测到错误)
  × P(定位到原因 | 已检测)
  × P(修复成功 | 已定位)
  × P(修复未引入新错)
```

这比把“校验器有效性”压成一个 `v` 更接近真实系统。测试可能善于发现问题却不能修复；critic 可能能提出问题却会误判；回滚可能恢复状态却浪费大量成本。

#### 变量五：资源效率——完成任务需要多少计算、状态和时间

要区分三个不同层次：

1. **算法复杂度**：注意力计算、KV cache、专家路由
2. **系统资源成本**：GPU 时间、内存、通信、并发利用率
3. **API 账单**：输入输出定价、缓存折扣、effort 档位

如果每一步都追加固定上下文、每轮重新读入全部历史且没有缓存或压缩，总输入 token 可呈二次增长。但真实 harness 会压缩、缓存、隔离和外置状态，因此 `n²` 只能看作一种无优化基线，不是普遍成本律。

#### 变量六：跨轨迹适应——系统能否从经验中改善

要区分四种不同的学习：

| 类型 | 更新对象 | 是否跨会话 | 是否修改主干权重 |
|:-----|:---------|:----------|:---------------|
| 会话内适应 | 当前上下文与临时状态 | 否 | 否 |
| 外部记忆 | 文件、数据库、Skill | 是 | 否 |
| 系统演化 | prompt、工具、harness 配置 | 是 | 否 |
| 参数学习 | 外置参数记忆或主干权重 | 是 | 是 |

“系统越用越好”不等于“模型在线学习”。文件记忆已经能让完整系统跨会话改善；权重是否变化是另一个问题。

## 三、2026 年的第一条主线：训练目标从答案正确转向轨迹回报

### 3.1 为什么 Agentic RL 重要

传统 SFT 提供的是：

```
给定输入 → 模仿一个目标输出
```

Agentic RL 提供的是：

```
给定目标与环境 → 执行动作 → 获得反馈 → 对整条轨迹优化
```

两者的根本差异不在于是否使用 RL，而在于**训练信号是否穿过了环境闭环**。模型只有在环境中行动，才能学到：

- 什么时候应该调用工具
- 工具失败后应该重试、换路径还是停止
- 哪些中间状态说明方向错了
- 如何在预算内完成任务
- 什么条件下应该交付而不是继续探索

这使 Agentic RL 成为 2026 年的重要方向。但它不是唯一解，也不是所有增益的唯一解释：更强的预训练、SFT 数据、工具设计、提示模板、推理预算和运行时验证都可能提高轨迹效用。

### 3.2 Kimi K3 揭示了环境工程的实际形态

Kimi K3 的技术报告披露了一套较完整的后训练流水线：

```
SFT
→ 编码 / Agentic / 通用推理 × 三档 effort，共九个 RL 专家
→ MOPD 多教师在线蒸馏回统一模型
```

其价值不在“九个专家”这个数字，而在于它展示了轨迹训练需要哪些基础设施：

| 机制 | 解决的问题 | 仍然存在的边界 |
|:-----|:-----------|:---------------|
| 在 Claude Code、Codex、OpenClaw、Hermes 等多种 harness 中随机化训练 | 降低对单一工具签名与提示模板的过拟合 | 无法保证对未见 harness 的泛化 |
| 超出 effort 预算奖励 −1 | 把成本纳入训练目标 | 固定预算可能压制必要探索 |
| Partial rollout | 避免超长轨迹拖慢整个训练批次 | 截断会影响长期信用分配 |
| Mock 应用环境 | 为办公任务制造可检查状态 | Mock 与真实系统存在分布差异 |
| 知识图谱任务合成 + verify-in-the-loop | 提高任务可解性与答案可验证性 | 验证器会继承知识图谱和模型的偏差 |
| Kernel 任务的 reward-hacking 检查 | 防止只优化 benchmark 表象 | 不可能穷举所有奖励漏洞 |
| 1M 上下文外置 KV pool | 支撑超长 rollout | 增加系统复杂度与通信成本 |

这说明未来训练资产的定义正在扩展：

```
过去：高质量数据集
现在：任务生成器 + 可交互环境 + 验证器 + 轨迹基础设施
```

把它概括为“环境即数据”有启发性，但仍不完整。更准确地说：**可重复、可评价、与真实部署足够相似的环境，正在成为新的训练资产。**

### 3.3 为什么代码能力提升最快

代码领域具备一组其他领域少见的条件：

- 环境可以复制
- 操作可以回滚
- 编译器和测试提供廉价反馈
- 成功条件相对明确
- 大量真实任务可从仓库与 issue 中提取

因此代码天然适合轨迹训练。Terminal-Bench、SWE-Bench Pro 等指标快速增长，与这一解释一致。

但不能据此严格推出“代码 → 数学 → 终端 → 浏览器 → 办公 → 创作”的固定进步顺序。各领域还受市场投入、数据规模、工具成熟度与评测设计影响。更稳妥的判断是：

> 在其他条件相近时，环境越可复制、反馈越廉价准确、错误越可回滚，越容易通过轨迹训练取得稳定进步。

### 3.4 推理时计算的位置发生了变化

第二篇把推理时计算视为提升单步质量的重要乘数，这个判断仍然成立。但 2026 年出现了两个补充：

1. **运行时推理受到成本和延迟约束。** 长轨迹中每一步都做 Best-of-N 或深度反思并不经济。
2. **部分探索能力可以通过后训练被内化。** 模型在大量带反馈的 rollout 中学习策略后，运行时可能用更少 token 完成同类任务。

GPT-5.5 相比 5.4“同延迟、更少 token、更高分”、GPT-5.6 Sol 在部分编码评测中以更少 token 获得更高分，与“部分推理成本被训练摊销”这一解释相容，但**不是直接证明**。Tokenizer、解码策略、工具协议、harness 和评测适配同样可能贡献增益。

因此更准确的趋势是：

> 推理时计算不会消失，而是在训练时探索、运行时按需推理、外部验证之间重新分配。

## 四、第二条主线：系统边界从模型扩展到模型—Harness 联合体

### 4.1 为什么同一个模型换 harness 会改变能力

模型并不直接接触世界。它看到的是 harness 选择、加工和排列过的信息；它能做的是 harness 暴露给它的动作。

因此轨迹策略实际是：

```
π(a_t | o_t; 模型, Harness)
```

Harness 至少影响四件事：

1. **观察**：哪些文件、历史和工具结果进入上下文
2. **动作空间**：有哪些工具，参数结构如何定义
3. **状态管理**：何时压缩、如何持久化、怎样隔离子任务
4. **治理**：哪些动作允许执行，何时需要审批或校验

所以“模型能力”在 Agent 场景中越来越不是单体属性，而是联合系统属性。Composer 2 在真实 Cursor harness 中训练、Kimi K3 在多 harness 环境中随机化训练，是这两种策略的直接体现：

- 在单一 harness 中训练：优化特定组合的上限
- 在多 harness 中训练：优化跨组合的鲁棒性

两者是不同目标，没有谁必然取代谁。

### 4.2 Harness 不是三类组件，也不会只剩一个薄壳

对 11 个主流 harness 的源码研究显示，它们普遍包含 loop、上下文管理、工具注册、子 agent、持久化、动态提示、生命周期 hook 和权限等模块。

这些模块不能被严格归约成互斥、完备的三类。更客观的功能划分是：

| 功能 | 典型机制 | 主要作用 |
|:-----|:---------|:---------|
| 决策运行时 | ReAct loop、动态工作流、程序化工具调用 | 执行模型产生的计划 |
| 上下文与状态 | Compaction、notes、session persistence | 控制信息密度和状态延续 |
| 任务分解 | Sub-agent、planner/executor、writer/reviewer | 并行、隔离或相互复核 |
| 工具与知识 | Tools、Skills、MCP | 扩展观察和动作空间 |
| 可靠性工程 | 测试、critic、检查点、重试、回滚 | 检测并恢复错误 |
| 治理 | 权限、沙箱、审计、人工审批 | 限制影响半径与风险 |
| 扩展机制 | Hooks、plugins、ACP | 接入外部运行时和客户端 |

### 4.3 编排迁入模型，但确定性流程不会消失

Opus 4.8 的 dynamic workflows 和 OpenAI 的 Programmatic Tool Calling 说明：模型正在生成部分编排逻辑，而不是由开发者预先写死全部路径。这印证了第一篇“业务决策向模型迁移”的判断。

但不能进一步推出“所有硬编码 workflow 都会消失”：

- 合规流程需要确定性审批
- 高风险操作需要固定门控
- 高频稳定任务用程序执行更便宜可靠
- 模型不擅长的步骤适合用确定性工具封装

更可能的终态是：

```
开放性高、路径未知的部分 → 模型动态编排
规则明确、风险高的部分   → 确定性流程
两者之间                 → Harness 负责边界与切换
```

这不是“less framework”或“more framework”的单向选择，而是**把不确定性留给模型，把确定性固化为系统约束**。

### 4.4 如何理解 Skills、MCP 与“无向量检索”

11 个 coding harness 中 9 个采用 Skills、8 个支持 MCP、没有一个把向量检索作为核心路径。这是有价值的观察，但它的适用边界是**编码类 agent 样本**：

- 代码库天然有文件名、符号和目录结构
- `grep`、编译器、语言服务器提供高精度检索
- 任务通常围绕当前仓库，而不是海量开放知识库

因此它支持的结论是：

> 在结构化程度高、可用精确工具检索的环境中，强模型主动选择工具可能优于在主循环中默认注入低信噪比的向量检索结果。

它不能证明向量检索会从所有知识场景消失。大规模文档库、多模态资产和跨组织搜索仍可能需要向量检索做候选召回。第四篇“向量检索退为预过滤层”的判断仍然合理，但目前不是普遍定律。

## 五、第三条主线：架构创新围绕轨迹经济性，而不是单纯追求参数规模

### 5.1 长轨迹为什么推动架构变化

轨迹每一步都可能读上下文、生成 token、调用工具。任务变长后，成本来自多个维度：

```
总成本
= 模型读写 token 的成本
+ KV cache 与内存成本
+ 专家路由与通信成本
+ 工具调用成本
+ 重试和验证成本
+ 人工介入成本
```

这比“token 数 × 单价”更接近真实成本。不同架构分别压低其中不同的项。

### 5.2 注意力：三条并存的降本路径

| 路线 | 代表 | 机制 | 解决什么 | 主要代价 |
|:-----|:-----|:-----|:---------|:---------|
| 压缩后稀疏选择 | DeepSeek V4 的 CSA / HCA | 对 KV 做不同程度压缩，再选取相关块 | 降低长上下文 KV 与注意力成本 | 索引器复杂度、压缩损失 |
| 线性注意力与全注意力混合 | Kimi K3 的 KDA + Gated MLA | 多层线性注意力间隔少量全注意力 | 让大部分层解码成本不随历史线性增长，同时保留内容寻址 | 状态压缩可能损失精确信息 |
| 块稀疏注意力 | MiniMax M3 的 MSA | 只对少数候选块计算注意力 | 硬件友好地减少计算 | 块选择错误会漏掉关键信息 |

三条路线都在减少全注意力的使用范围，但不能据此说“全注意力是唯一能保证精确召回的机制”。全注意力本身也不保证模型一定利用正确位置；外部索引、检索和可寻址记忆也能提供精确访问。

更稳妥的趋势判断是：**全注意力将与压缩、线性或稀疏机制长期混合，而不是被完全替代。**

### 5.3 MoE：把知识容量和单 token 计算解耦

- Kimi K3：896 个专家中激活 16 个，稀疏度 56
- DeepSeek V4-Pro：1.6T 总参数、约 49B 激活参数
- Qwen3.8-Flash-Next：125B 主干、约 6B 激活

MoE 的价值是总容量可以增长，而每个 token 只经过少数专家。但“激活参数决定推理成本下限、与总参数无关”仍然过度简化：专家权重搬运、跨卡通信、负载均衡、批大小和硬件利用率都会影响成本。

Kimi K3 的 Stable LatentMoE、Quantile Balancing 与 Per-Head Muon，DeepSeek V4 的大规模 Muon 与确定性 kernel，说明稀疏度继续提高后，**训练稳定性和系统利用率成为与理论 FLOPs 同等重要的问题**。

### 5.4 Engram：更应理解为计算—存储分工，而不是在线学习前夜

Engram 的核心是条件记忆：根据 N-gram 哈希做近似 O(1) 查表，再将取出的向量与隐状态融合。论文发现 MoE 参数与记忆参数之间存在 U 型 scaling law；27B 实验中 MMLU、BBH 和 NIAH 均有提升。Qwen3.8-Flash-Next 使用 51B N-gram 嵌入表，是这条路线的第二次大规模验证。

它最可靠的含义是：

> 一部分稳定、高频、可索引的模式，可以从每次动态计算转为存储与查找，用便宜的内存容量替代昂贵的计算容量。

这与第四篇“知识供给下沉到模型原生基础设施”的方向一致。

但 Engram 是训练时写入的静态表，不能直接推出“推理时可写的参数记忆”。在线写入还需要解决：

- 新旧记忆冲突
- 错误和恶意内容投毒
- 遗忘与容量管理
- 多用户隔离
- 审计与回滚

因此“可写 Engram”应被视为候选研究路径之一，而不是下一代模型的必然形态。

### 5.5 Effort：质量、延迟和成本之间的显式控制面

Opus 4.6 的四档 effort、Opus 4.7 的 xhigh、DeepSeek V4-Pro 的多档 effort、Fable 5.1 的 per-message effort，说明模型厂商正在把推理预算变成 API 的标准控制面。

Kimi K3 在训练中按 effort 分专家并对超预算轨迹给负奖励，进一步说明不同预算下的最优策略不同。低预算不是简单截断高预算思维链，而可能需要模型学会更直接地行动。

这里可以做一个相对可靠的判断：

> 未来模型竞争不仅比较“最高能力”，也比较在给定质量、成本和延迟约束下的 Pareto 前沿。

“同分少 token”是这个前沿改善的一种表现，但不能脱离 tokenizer、缓存、工具调用和完成率独立比较。

## 六、第四条主线：记忆正在扩展系统状态，但持续学习尚未解决

### 6.1 先把“记忆”拆开

2026 年被称为“记忆”或“自进化”的机制其实属于不同层次：

| 层次 | 代表 | 能解决什么 | 不能解决什么 |
|:-----|:-----|:-----------|:-------------|
| 会话压缩与 notes | Opus compaction、Codex notes | 跨上下文窗口延续任务状态 | 不能跨项目形成稳定经验 |
| 文件记忆 | Fable 5 游戏实验、AGENTS.md | 保存事实、偏好和显式纠正 | 依赖模型正确写入与读取 |
| Skill 沉淀 | Hermes Agent、Claude Skills | 复用可表达的流程与方法 | 难以表达隐性技能和直觉 |
| Harness 自改 | Continual Harness | 调整工具、提示和流程 | 容易积累错误配置，需要评测和回滚 |
| 参数学习 | Nested Learning、Hope、Titans 等研究 | 有潜力内化隐性和程序性经验 | 遗忘、安全与审计尚未解决 |

`doubao-seed-evolving` 是固定 model ID 背后的周级滚动更新，不是用户交互触发的在线学习。

### 6.2 文件层并不是“α = 0”

如果研究对象是完整 Agent 系统，文件记忆和 Skill 已经让系统能够跨会话改善。说“α 仍为零”是不准确的；只能说**主干模型权重没有在线更新**。

文件层的优势是可读、可审计、可回滚、可隔离。它的局限是：

- 只能记录模型能够显式表达的经验
- 读取会占用上下文
- 错误记忆可能被反复放大
- 记忆选择本身也是一次不可靠决策

ARC-AGI-3 这类交互式基准对“在陌生环境中现场学习”提供了有价值的信号，但单一分数无法诊断提升究竟来自上下文策略、工具、记忆还是权重机制。

### 6.3 未来不是一条“文件 → 参数”的直线

更可能出现的是分层共存：

```
可审计的事实与偏好       → 外部文件 / 数据库
稳定的流程与规范         → Skill
会话内临时状态           → Context / Notes
高频、稳定、可索引模式   → 参数化外置记忆
隐性程序能力             → 主干权重或专用适配器
```

哪一层胜出取决于更新频率、错误代价、隐私和审计要求。持续学习的核心问题不是“能否写入”，而是**能否证明写入带来的长期净收益大于遗忘与投毒风险**。

## 七、第五条主线：安全从内容治理扩展到轨迹治理

### 7.1 风险不能只写成“能力越强越危险”

一条轨迹的风险至少由四项共同决定：

```
风险
≈ 危险目标出现的概率
× 获得相应权限的概率
× 成功执行的概率
× 后果影响
```

提升 Agent 能力主要提高第三项，但最小权限、沙箱和人工审批可以压低第二项，回滚与影响隔离可以压低第四项。

因此安全并不必然要求某一种“分类器回退架构”。可选干预包括：

- 输入与目标分类
- 工具级权限
- 中间动作监控
- 沙箱和网络隔离
- 高风险步骤人工审批
- 速率限制与预算限制
- 事后审计和回滚

### 7.2 2026 年的信号

**Mythos Preview / Project Glasswing。** Anthropic 没有公开发布该模型，而是定向提供给防御机构。其漏洞发现能力显著高于 Opus 4.6。这表明能力评估正在影响发布范围，但单个案例不足以证明以后所有最强模型都不公开。

**GPT-6 Astra。** OpenAI 将其网络能力评为 Preparedness 框架 Critical 级，并配套 Daybreak 计划。这说明前沿能力评测与治理正在合流。

**Fable 5 分类器回退。** 高风险请求回退到 Opus 4.8，是模型路由与安全策略结合的生产实例。但入口分类器不等于完整的轨迹监控；真正的轨迹治理还要检查中间动作和权限变化。

**Hugging Face 事件。** 数据集投毒影响训练节点并导致凭证风险，说明“环境与验证器成为训练资产”后，训练流水线本身也成为供应链攻击面。

**OpenClaw 安全事件。** 恶意 Skills、暴露实例和高危漏洞说明 Skill 市场本质上是软件供应链，需要签名、来源验证、沙箱与最小权限。

### 7.3 为什么漏洞发现可能暂时快于修复

漏洞发现通常有明确反馈：崩溃、越权、利用成功。修复则需要理解原意、保证兼容并避免回归，评价标准更复杂。

因此“验证反馈越清晰的任务越容易通过轨迹训练提升”可以解释发现与修复能力的不对称。但这只是一个重要因素，代码库测试覆盖、维护者响应能力和组织流程同样决定修复速度。

## 八、真正的结构性趋势：从机制堆叠中抽出五条主线

### 趋势一：优化单位从模型响应变为闭环轨迹

**证据强度：高。**

评测、训练和产品都在围绕长程环境交互重构。模型不再只要“会回答”，还要会行动、观察、恢复和终止。

这条趋势能解释：

- Agentic RL 环境增多
- Terminal-Bench、OSWorld 等基准重要性上升
- Harness 与模型联合训练
- 成本从 token 单价转向任务总成本

### 趋势二：稀缺资产从文本数据扩展为“可评价环境”

**证据强度：中高。**

高质量文本仍然重要，但轨迹训练还需要环境、任务生成器、反馈与验证器。Kimi K3、ToolVerse、NeMo Gym、ScaleCUA / VeriGen 都支持这一判断。

需要保留的反例是：部分能力仍可通过预训练数据、SFT 或合成文本显著提升；环境工程并非所有能力的主要瓶颈。

### 趋势三：系统边界从模型扩展到模型—Harness—工具

**证据强度：高。**

模型对工具格式、上下文策略和运行时约束高度敏感；应用厂商开始在真实 harness 中训练模型，基础模型厂商也开始做跨 harness 鲁棒训练。

这意味着未来评测必须固定并公开 harness，否则“模型分数”不可复现。

### 趋势四：Scaling 的衡量单位从“模型有多大”转向“单位资源完成多少有效工作”

**证据强度：高。**

MoE、稀疏注意力、FP4、缓存、effort 和 fast mode 的共同目标不是同一种架构，而是改善质量—成本—延迟的 Pareto 前沿。

“每百万 token 价格”会继续存在，但企业选型更应关注：

```
单位成功任务成本
= 一次任务平均总成本 / 任务成功率
```

### 趋势五：自主性与控制能力共同成为产品能力

**证据强度：中高。**

模型越能自主完成长轨迹，权限、审计、回滚与门控越重要。Harness 不会因为模型更强而消失；它会减少对业务路径的硬编码，同时增强状态管理和治理能力。

### 尚未成为趋势的方向：权重级持续学习

**证据强度：低。**

目前有研究方向和外部记忆实践，但缺少生产级、可审计、可证明长期净收益的在线权重学习。它值得跟踪，不适合写成“下一个代际必然由此定义”。

## 九、2026 年证据矩阵：事实、解释与不确定性分开

| 事件 | 可以确认的事实 | 最合理的机制解释 | 不能据此证明的结论 |
|:-----|:---------------|:-----------------|:-------------------|
| Opus 4.6：1M、compaction、agent teams、effort | 产品同时强化长上下文、状态管理与并行 Agent | 面向长轨迹的联合系统优化 | Anthropic 一定采用某种特定稀疏注意力 |
| GPT-5.5 / 5.6：部分评测更高、token 更少 | 质量—token 前沿改善 | 后训练、解码与 harness 优化共同作用 | 增益全部来自 RL，或推理已完全摊销进权重 |
| DeepSeek V4：CSA/HCA、低 KV、FP4、Muon | 公布了明确架构机制 | 以存储与计算效率支撑长上下文 | 闭源模型一定采用相同结构 |
| V4 Preview → 0813 大幅涨分 | 短期内 Agentic 指标提升 | 后训练和系统优化可能贡献显著 | 预训练 checkpoint 完全没变，或增益只有 RL |
| Kimi K3 多 harness RL | 训练环境显式随机化 harness | 试图提升跨 harness 鲁棒性 | 已经解决所有 harness 过拟合 |
| Composer 2 在 Cursor harness 中训练 | 应用环境进入训练分布 | 优化模型—产品组合 | 模型离开 Cursor 必然失效 |
| 11 个 coding harness 不用向量检索 | 在该样本中成立 | 代码结构与精确工具检索更适合主循环 | 向量检索在所有 Agent 中都会消失 |
| Engram 与 Qwen N-gram 记忆表 | 条件记忆在两个架构中出现 | 用存储替代部分动态计算 | 在线可写参数记忆即将成熟 |
| Mythos 不公开、Astra Critical | 能力评估影响发布与治理 | 自主能力提高要求更强门控 | 以后所有最强模型都不会公开 |
| Fable 5 文件记忆实验 | 外部状态带来任务增益 | 显式经验复用有效 | 模型权重具备在线持续学习 |

这张表是全文最重要的方法约束：**一手事实只能支持有限强度的机制推断，机制推断不能自动升级为趋势必然性。**

## 十、未来 12–24 个月：分置信度判断，而不是宣布终局

### 10.1 高置信判断

#### 判断一：模型评测会越来越要求固定 harness 和报告总成本

理由：模型与工具定义、上下文策略、推理预算高度耦合。只报告模型名和最终分数，已无法解释性能来源。

观察指标：

- Benchmark 是否公开 harness、工具 schema 与 effort
- 是否同时报告成功率、耗时、输入输出 token 和重试次数

可能改变判断的证据：同一模型跨主流 harness 的结果差异持续收敛到评测噪声范围。

#### 判断二：轨迹训练和环境工程投入继续增长

理由：代码、终端、浏览器和办公 Agent 都需要环境反馈；现有厂商披露和开源工具链均在增长。

观察指标：

- 可用环境和验证器数量
- 真实任务与 mock 环境之间的泛化差距
- 长轨迹 RL 的单位训练成本

可能改变判断的证据：纯文本预训练或 SFT 在 Agentic 指标上持续取得同等增益，且成本更低。

#### 判断三：混合注意力、稀疏 MoE 与低精度训练继续普及

理由：它们分别改善长上下文、激活计算和内存带宽，符合推理规模快速增长的经济约束。

可能改变判断的证据：新的稠密架构在相同质量下取得更优的端到端成本与延迟。

### 10.2 中等置信判断

#### 判断四：Harness 形成稳定内核，但确定性 workflow 与模型编排长期共存

稳定内核可能包括状态管理、工具注册、权限、审计、检查点和恢复；业务路径则根据任务开放程度在程序与模型之间分配。

不确定性：协议竞争、产品垂直化和安全监管可能导致多个不兼容内核长期并存。

#### 判断五：长上下文竞争从窗口大小转向有效信息密度与单位任务成本

窗口大小仍是资源边界，不会“死亡”；但只宣传 1M 或 10M 的价值下降。用户更关心关键证据利用率、压缩损失、缓存命中率和完成任务总成本。

不确定性：市场营销和部分超长文档场景仍可能继续推动窗口数字竞争。

#### 判断六：能力门控和分级发布更普遍

Mythos、Astra 和 Fable 5 提供了早期信号。更强的网络与 CUA 能力会推动模型路由、权限分层和防御计划。

不确定性：监管、竞争与开源泄漏可能阻止统一的分级发布模式形成。

### 10.3 低置信、值得跟踪的假说

#### 假说一：出现生产级可写参数记忆

可能路径包括动态 Engram、专用记忆网络、适配器或受约束在线更新。关键验收标准不是 benchmark，而是：

- 跨会话稳定增益
- 不损害旧任务
- 可隔离、可审计、可回滚
- 能抵御恶意写入

#### 假说二：任务级或结果级计费成为主流

技术上它更符合用户价值，商业上却面临任务难度定义、失败责任和成本波动问题。短期更可能先出现“固定额度 Agent 套餐”，而不是严格按结果付费。

#### 假说三：最强模型长期不公开

目前只有少数案例，不能据此宣布常态化。开源追赶、监管要求和市场竞争都会影响发布策略。

#### 不再保留的断言：开闭源差距稳定在 3–6 个月

“差距”缺乏统一量纲：数学、编码、网络、中文、成本和部署能力的差距不同；公开模型与内部模型也不可直接比较。3–6 个月可以描述部分历史案例，不足以成为稳定规律。

## 十一、对前四篇判断的客观复核

| 原判断 | 2026 年证据 | 当前结论 |
|:-------|:------------|:---------|
| 01：长链任务放大局部能力差异 | 长程 Agent 体感与评测继续支持 | **保留核心直觉**；`p^n` 降为独立、同质、不可恢复步骤的特例 |
| 01：Agent 能力有短板效应 | 工具、上下文、恢复任一薄弱都能使任务失败 | 保留，但系统还受错误相关性和恢复能力影响 |
| 01：业务编排从框架迁入模型 | Dynamic workflows、Programmatic Tool Calling | 部分兑现；确定性流程不会消失 |
| 01：Harness 会越来越薄 | Harness 的状态管理、权限、子 agent 持续增强 | **原判断不完整**；业务编排变薄，可靠性与治理内核变厚 |
| 01：模型能力快速商品化 | 中档模型追赶前代旗舰、开源能力提升 | 部分成立；前沿能力门控可能维持差异 |
| 01：评测能力是稀缺资源 | Harness、effort 和任务分布使分数难比较 | 强化；需升级为轨迹级评测 |
| 02：推理时计算是关键乘数 | 深度推理仍有效，但成本与验证限制明确 | 保留但降级；它是训练时与运行时计算配置的一部分 |
| 02：PRM / 验证器是重要方向 | Agentic GRM、逐步 credit assignment、环境验证增多 | 兑现，但验证器不是唯一瓶颈 |
| 02：精调只是最后一公里 | 传统领域 SFT 的战略地位下降 | 需修正；基于私域环境的后训练可能成为新定制方式 |
| 03：Skill 的渐进披露有优势 | Coding harness 中 Skills 采用广泛 | 在编码 Agent 范围内得到支持，不能外推到所有场景 |
| 04：向量检索退为预过滤层 | 研究样本中的 coding harness 不以向量检索为主 | 有条件支持；大型知识库仍可能依赖向量召回 |
| 04：知识供给向模型原生基础设施演化 | Engram、Qwen N-gram 表提供架构证据 | 支持“计算—存储分工”，尚不能证明动态记忆终局 |

这张表与旧版本最大的区别是：允许结论为“原判断不完整”“证据只在局部成立”或“尚不能证明”，而不是只在继承、兑现和强化之间选择。

## 十二、架构师如何从被动跟进转为主动判断

### 12.1 不再问“这个模型强不强”，而问六个问题

1. **优化对象是什么？** 单轮问答、代码 patch，还是完整工作流？
2. **成功标准是否可验证？** 是自动测试、模型评分还是主观判断？
3. **关键路径有多长？** 不看工具调用总数，看不可并行、不可省略的决策数。
4. **错误如何恢复？** 能否检测、定位、回滚，失败影响半径多大？
5. **完整成本是多少？** 模型、缓存、工具、重试、人工和延迟都要计算。
6. **性能来自哪一层？** 模型权重、推理预算、harness、工具还是环境适配？

这六个问题比追踪 model name 更稳定。

### 12.2 企业建设优先级

**第一优先：轨迹级评测。**

建立 10–20 个真实工作流，记录最终效用、失败位置、恢复次数、总成本、耗时和人工介入。没有它，就无法区分模型升级和 harness 调整的真实收益。

**第二优先：可回滚的环境与工具。**

把私域系统提供为最小权限、可观测、幂等或可回滚的工具。它同时提高运行时可靠性，并为未来轨迹训练积累环境资产。

**第三优先：外部记忆与 Skill，但必须有治理。**

记录来源、更新时间、适用范围和回滚历史；把 Skill 视为可执行供应链，而不是普通文档。

**第四优先：模型与 harness 解耦，但承认它们存在联合优化。**

接口层保持可替换，同时为不同组合维护独立评测结果。不要假设换一个兼容 API 的模型就能保持原有轨迹质量。

**第五优先：按风险分配自主性。**

低风险、可回滚任务允许模型动态编排；高风险、不可逆任务使用固定流程、权限门控和人工审批。

### 12.3 信号清单

| 信号 | 能说明什么 | 不能说明什么 |
|:-----|:-----------|:-------------|
| RL 环境数量、验证器类型、轨迹长度 | 后训练基础设施投入 | 最终泛化一定提高 |
| 同模型跨 harness 对比 | 模型—harness 耦合程度 | 模型单体能力高低 |
| 成功率 × 总成本 × 耗时 | 实际轨迹效率 | 具体增益来自哪种内部机制 |
| 同一模型多长度曲线 | 上下文利用随长度的变化 | 换模型后的普遍规律 |
| KV、激活参数、端到端吞吐 | 架构效率线索 | API 最终定价 |
| ARC-AGI-3 等交互基准 | 会话内适应能力 | 权重是否在线学习 |
| 分类器、权限、沙箱、回滚率 | 治理成熟度 | 模型本身是否“对齐” |
| 厂商定价 | 商业定位和部分成本信号 | 内部架构与真实边际成本 |

## 十三、收尾：真正的转折是从“会回答”到“能闭环”

第二篇用“考试”解释推理时计算：训练时计算是考前学习，推理时计算是考试时多检查。2026 年更像是模型从考试走向了工作现场。

考试有确定题目、有限时间和标准答案；工作现场有持续变化的状态、不完整信息、工具故障、权限边界和模糊目标。进入工作现场后，模型分数不再足以描述系统能力：

- 后训练让模型在环境反馈中练习行动策略
- Harness 决定它能看到什么、能做什么、如何恢复
- 架构创新决定一条长轨迹是否经济可行
- 记忆决定经验能否跨轨迹复用
- 安全机制决定错误与滥用的影响边界

这些机制没有一个是唯一解，也不能从一个简化公式中必然推出。它们共同指向的，是优化对象的改变：

> **大模型竞争正在从“谁能生成更好的下一段文本”，转向“哪个模型—Harness—环境组合能以更低成本、更低风险完成更有价值的闭环轨迹”。**

这是一条比模型命名和单项 benchmark 更稳定的观察主线。

未来真正值得关注的，也不是某个模型是否又提高两分，而是三个更困难的问题：

1. 系统能否在开放环境中稳定完成更长的关键路径？
2. 这种能力能否在成本、延迟和安全约束下规模化？
3. 系统能否从经验中获得可证明、可审计、不会破坏旧能力的长期改善？

前两个问题定义了 2026 年。第三个问题，仍然没有被解决。
