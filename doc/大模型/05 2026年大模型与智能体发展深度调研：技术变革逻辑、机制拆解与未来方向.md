# 2026 年大模型与智能体发展深度调研：技术变革逻辑、机制拆解与未来方向

作者：向春（架构师）
日期：2026-09-10
背景：作为系列第五篇，本文回应一个非常具体的困扰——2026 年以来，从 Opus 4.6 的惊艳，到 Kimi K3、DeepSeek V4 等国产模型密集发布，再到各种智能体 harness 的涌现，我们**能看到效果，却难以敏锐感知底层的技术变革逻辑和具体机制，只能被动跟进**。本文基于对 2026 年 1 月至 9 月主要厂商公告、技术报告（Kimi K3、DeepSeek V4/mHC/Engram、Continual Harness、harness 工程研究等）、独立评测与安全事件的系统梳理，试图做三件事：把 8 个月的事件流压缩成一张可读的时间线；把表面的"效果"还原为五条底层技术主线及其具体机制；给出未来 12–24 个月的方向研判，以及一套让架构师从"被动跟进"转为"主动感知"的观察框架。

## 〇、调研概述与核心结论

### 0.1 为什么会"看得到效果、看不到机制"

这不是个人敏感度的问题，而是这一轮技术变革的结构性特征决定的：

1. **变化的主战场从预训练转移到了后训练和 RL 环境**。2023–2024 年，能力提升主要靠参数规模与数据规模，厂商乐于公布"多少 B 参数、多少 T tokens"。2026 年的能力跃迁主要来自 agentic RL——环境怎么建、奖励怎么设计、credit 怎么分配——而这部分恰恰是厂商披露最少的。闭源厂商的发布公告只讲 benchmark 和产品功能，不讲训练配方。
2. **harness 层的创新以"产品功能"的面貌出现**。context compaction、agent teams、dynamic workflows、effort 参数——这些其实是系统层面的技术机制，但用户看到的是 Claude Code 里多了一个功能、Cursor 里多了一个窗口。机制被产品化包装后，技术脉络就被切碎了。
3. **架构层的创新只在开源技术报告中可见**。mHC、Engram、KDA 混合注意力、Attention Residuals、CSA/HCA 交替稀疏注意力、Stable LatentMoE——这些名字全部来自国产开源模型的技术报告。闭源模型是否用了类似机制，只能从行为（1M 上下文的价格、延迟）反推。
4. **发布节奏压缩到了 6 周级**。Anthropic 在 2 月、4 月、5 月、6 月、7 月、9 月各发一代；OpenAI 在 2 月、3 月、4 月、6–7 月、9 月各发一代。当代际间隔短于消化周期，信噪比自然下降。

因此，正确的应对不是"跟得更快"，而是建立一个**分层的阅读框架**：把每一条新闻归入"架构 / 后训练 / harness / 部署经济"四层中的一层，再判断它是否改变了该层的主线判断。本文第二章就是这个框架的展开。

### 0.2 核心结论（先给答案）

**结论一：Scaling 找到了第三条轴——agentic RL 与环境工程，它是 2026 年能力跃迁的主因。** 预训练 scaling 的边际收益下降是共识，但 2026 年模型在 Terminal-Bench、SWE-Bench Pro、OSWorld 上的成绩仍在以每半年 15–25 个百分点的速度增长。增长来自 RL 环境的规模化：Kimi K3 报告披露了一套可实例化 Claude Code / Codex / OpenClaw / Hermes 等多种 harness 的白盒 RL 环境，单次 rollout 达数千次工具调用、百万 token；OpenAI 披露内部编码推理算力 6 个月增长 100 倍、agentic token 增长 22 倍。**环境即数据**，谁能以更低成本合成、验证和调度更多样的长程环境，谁就掌握了新的 scaling 曲线。

**结论二：百万上下文完成了从"能用"到"经济"的转变，靠的不是单点突破，而是注意力、深度、宽度、记忆、数值精度五个维度的组合创新。** DeepSeek V4 用 CSA（4× 压缩 + FP4 索引 top-k）与 HCA（128× 压缩）交替，把 KV cache 压到约 2%；Kimi K3 用 KDA（线性注意力）3 层 + Gated MLA 1 层的混合比例；MiniMax M3 用块稀疏注意力把 1M 上下文的单 token 注意力计算降到 1/20。深度方向 mHC 与 Attention Residuals 让超深网络可训练；宽度方向 Stable LatentMoE 把稀疏度推到 56；Engram 把"记忆"从注意力中剥离成 O(1) 查找。这些机制加在一起，才有 Opus 4.6 在 1M MRCR v2 上 76%（Sonnet 4.5 仅 18.5%）这种"效果"。

**结论三：竞争主轴正从"绝对能力"转向"每单位 token 的能力"，effort 可控化是这一转向的技术载体。** GPT-5.5 与 5.4 同延迟、更少 token 却分数更高；GPT-5.6 Sol 在 Coding Agent Index 上高于 Fable 5 2.8 分而 token 用量少一半；Opus 4.7 引入 xhigh、Kimi K3 训练 3 域 × 3 effort = 9 个 RL 专家再蒸馏；Gemini 3.8 Flash 反向选择"works harder"（多用 30% token 换分数）。Gartner 所谓"推理悖论"（token 单价到 2030 年降 95%，但 agentic 工作流的推理成本到 2028 年涨 5 倍以上）说明：**token 效率已经是产品定价和架构选型的一等公民**。

**结论四：Harness 成为能力的第二来源，且模型与 harness 进入共演化阶段。** "Agent = Model + Harness" 已成行业共识。对 11 个主流 harness 源码的研究显示它们无一依赖通用框架、无一使用向量检索、9/11 采用 Skills；Claude Code 的 dynamic workflows 让模型自己写编排脚本调度数十到数百个子 agent；Cursor Composer 2 直接在真实 harness 中做 RL；Kimi K3 为了防止过拟合单一 harness 而在 RL 中随机切换 harness。**harness 从"模型的外壳"变成了"训练的一部分"**，这是 2026 年最容易被低估的结构性变化。

**结论五：记忆与持续学习是尚未突破的最后一环，当前所有"自进化"都是 harness 层的文件/技能沉淀，而非权重层的在线学习。** Fable 5 用文件记忆在 Slay the Spire 上取得 3 倍增益，Hermes Agent 自动沉淀 SKILL.md，Continual Harness 用 reset-free CRUD 让 agent 自改 harness——它们都不改权重。ARC-AGI-3（交互式、要求现场学习）上最强模型仅 1.5–5.2%，说明"在环境中学习"仍是硬问题。豆包 `doubao-seed-evolving` 是周级滚动替换权重，不是在线学习。**谁先把"记忆"从文件系统搬进参数（或参数化的外置记忆），谁就开启下一个代际。**

**结论六：安全从"发布附带的红线"变成了"发布的前置门控与架构组件"。** Claude Mythos Preview 因网络能力过强而不公开发布（Project Glasswing 仅向 40+ 机构开放）；GPT-6 Astra 是首个 Preparedness 框架 Critical 级网络风险的模型；GPT-5.6 预览版接受政府预审；Fable 5 采用"分类器命中即回退 Opus 4.8"的双模型架构。Hugging Face 事件（内部模型 + 数据集投毒 → 节点权限 → 窃取凭证）导致 OpenAI 暂停 RL 训练约两周。**安全能力门控正在成为模型分层的一部分**，而不只是合规部门的事。

**结论七：开源与闭源的差距稳定在 3–6 个月，国产模型选择了"效率优先"的差异化路线，并在办公 Agent 产品层展开正面竞争。** DeepSeek V4-Pro-0813 在 Terminal-Bench 2.1 上 87.9 分、Kimi K3 在 WebDev Arena 登顶、Qwen3.8-Flash-Next 以 1/9 的训练成本逼近前代旗舰。国产路线的共同特征：超大稀疏 MoE + 低激活 + FP4/MXFP4 量化感知训练 + Muon 优化器 + 条件记忆，用架构效率对冲算力约束。产品层，QwenWork 上线一月 3000 万用户，豆包工作、Kimi Work、腾讯 WorkBuddy、金山灵犀、百度 DuMate 同月密集上线，办公 Agent 成为国内的主战场。

### 1.3 节奏、命名与定价的结构性变化

**节奏：代际间隔从 6 个月压到 6 周。** Anthropic 2026 年至 9 月发布了 Opus 4.6/4.7/4.8、Fable 5、Sonnet 5、Opus 5、Fable 5.1、Mythos 5 共 8 个模型。这在预训练主导时代是不可能的（一次预训练就要数月）。它只有一个解释：**这些代际的大部分差异来自后训练，而后训练的迭代周期是周级的**。Grok 4.6 官方明确说"仅后训练升级"，DeepSeek V4-Pro 从预览到 0813 在 Terminal-Bench 上 +16 分也未换预训练底座。

**命名：从"大小"到"档位"。** OpenAI 的 Sol/Terra/Luna、Anthropic 的 Fable/Opus/Sonnet 本质上都是三档定价 tier，且 tier 内部再有 effort 档位。Fable 高于 Opus、Sonnet 5 在部分 agentic 指标上超过 Opus 4.8，说明"大小"已不足以描述模型——**模型 = 底座 × 后训练配方 × effort 预算 × 安全门控**，命名只能反映商业定位。

**定价：名义价格不变，实际成本被三个隐性变量重定义。** (1) tokenizer 税：Opus 4.7 新 tokenizer 同文本 1.0–1.3×，Sonnet 5 再 +30%；(2) effort：同一模型 max 与 low 的 token 用量可差数倍；(3) 缓存：Fable 5.1 cache read 降 75%，对长会话 agent 而言缓存命中率比标价更重要。结论是：**比较模型成本必须用"完成同一任务的总 token 费用"，而不是每百万 token 的标价**。

## 二、五条底层技术主线：机制拆解

这一章是本文的核心。把 2026 年所有"效果"归入五条主线，每条主线回答三个问题：它解决什么矛盾、具体机制是什么、从哪些公开信号可以验证。

### 2.1 主线一：Scaling 的第三条轴——agentic RL 与环境工程

#### 2.1.1 矛盾

预训练 scaling（更多参数、更多数据）的边际收益递减已是共识；推理时计算 scaling（更长思维链、多路径搜索，本系列第二篇的主题）在 2025 年被充分挖掘，但它有个天花板——**它只能放大模型已有的能力，不能教模型新的行为模式**。长程 agentic 任务需要的恰恰是新行为：在数百步中保持目标、在失败后回退、判断何时该调用工具、何时该停止。

回到本系列第一篇的乘法衰减定律：一个 H 步任务的成功率约为单步可靠性 p 的 H 次方。2026 年的独立长程评测（LongHorizon 系列）给出了量化结论：**当 H > 200 时，单步可靠性需超过 99.65% 才能保证任务成功率过半**。这意味着单靠推理时计算已不够，必须在训练阶段直接优化长程行为。

#### 2.1.2 机制：环境即数据

**（1）RL 环境规模化成为新的数据工程。** Kimi K3 技术报告是目前对此披露最完整的一手资料，它的后训练流水线是：

```
SFT
 → 3 个领域（编码 / agentic / 通用推理）× 3 个 effort 档位 = 9 个 RL 专家模型，各自独立训练
 → MOPD（Multi-teacher On-Policy Distillation）：9 个专家在线蒸馏回一个统一模型
```

关键在于 RL 阶段的环境：
- **统一白盒 RL 环境可实例化多种 harness**（Claude Code、Codex、OpenClaw、Hermes 等），训练时随机切换，明确目的是**防止模型过拟合单一 harness 的工具签名和提示模板**。
- **个人助理场景用 mock 应用做 rollout**，单条轨迹达数千次工具调用、百万 token；1M 上下文 RL 靠外置 KV pool 支撑。
- **知识图谱驱动的任务合成**：从知识图谱采样实体和关系生成需要多跳检索的任务，保证任务有可验证答案。
- **AET（verify-in-the-loop）**：生成的任务先由模型尝试解答并验证，过滤掉不可解或答案错误的任务。
- **kernel 优化任务内置 reward-hacking 检测**：因为 RL 会找到"让 benchmark 变快但语义不对"的捷径。
- **partial rollout**：对超长轨迹截断并异步继续，解决长程 RL 中的 straggler 问题（一条百万 token 的轨迹会让整批等待）。

DeepSeek V4 同样采用 on-policy distillation，公开 RL 环境框架（ScaleCUA 的 VeriGen 验证生成、ToolVerse 的 422 个 MCP 环境 / 4438 个工具、NVIDIA NeMo Gym）在 2026 年集中出现，说明**环境工程正在形成独立的工具链**。

**（2）奖励从结果判别转向过程评分与预算约束。** Kimi K3 的 Agentic GRM（Generative Reward Model）用 rubric 逐项打分，同时控制 verbosity；**超出 effort 预算的轨迹直接奖励 −1**，这是 effort 可控化的训练侧来源（详见主线三）。学术界的 TRCA / TRACE / HiPER 等工作则在做逐步 credit assignment——长程任务里哪一步该被奖励、哪一步该被惩罚，这是 RL 长程化的核心难题。

**（3）算力从预训练转向 RL 推理。** OpenAI 披露内部编码推理算力 6 个月增长 100 倍、agentic token 增长 22 倍；Hugging Face 事件后 OpenAI 暂停 RL 训练约两周并搁置最大的 RL run——**RL run 已经是与预训练 run 同等量级的资源单位**。

#### 2.1.3 可验证的信号

- 同一底座短期内 agentic 指标大幅提升（DeepSeek V4 预览 → 0813：Terminal-Bench 72.1 → 87.9；Grok 4.6 仅后训练）。
- 模型对不同 harness 的鲁棒性差异（K3 在 Claude Code / Codex 中表现接近，而早期模型换 harness 掉分明显）。
- 厂商开始公布"RL 环境数量 / 工具数量"而非"训练 token 数"。

### 2.2 主线二：百万上下文的经济化——五个维度的组合创新

#### 2.2.1 矛盾

2025 年已有 1M 上下文的模型，但两个问题未解：**质量**（长上下文中间部分召回差，"lost in the middle"）和**成本**（KV cache 随长度线性增长，注意力计算随长度平方增长，1M 上下文的解码几乎不可服务）。Opus 4.6 在 1M MRCR v2 上从 18.5% 跳到 76%、DeepSeek V4 把 KV cache 压到约 2%、MiniMax M3 把注意力计算降到 1/20，靶向的都是这两个问题。

#### 2.2.2 机制：注意力 × 深度 × 宽度 × 记忆 × 精度

**（1）注意力：三条路线并存。**

| 路线 | 代表 | 机制 | 取舍 |
|---|---|---|---|
| **压缩 + 稀疏选择** | DeepSeek V4（CSA / HCA） | CSA：KV 4× 压缩后，用 FP4 精度的 lightning indexer 对压缩块打分取 top-k；HCA：128× 重度压缩，覆盖全局。61 层中前 2 层用 HCA，其余 CSA/HCA 交替；MTP 块采用滑窗。KV cache 降至约 2% | 保留精确检索能力，代价是索引器的额外计算与训练复杂度 |
| **线性化 + 少量全注意力** | Kimi K3（KDA + Gated MLA） | KDA（Kimi Delta Attention，线性注意力变体）3 层配 1 层 Gated MLA（NoPE，无位置编码）。KDA 用下界衰减 g_min = −5 保证对角 tile 全部可用 Tensor Core 计算，输出门全秩 | 线性层解码 O(1) 状态，全注意力层保证精确召回；比例 3:1 是效率与召回的折中 |
| **块稀疏** | MiniMax M3（MSA） | 每 query 只对 top-16 个 128-token 块做注意力 | 实现简单、硬件友好，长程精确性依赖块选择器质量 |

三条路线的共同点：**全注意力只保留在少数层或少数块**，其余用压缩、线性化或稀疏替代。这与闭源模型行为一致——Opus 4.6 的 1M 上下文以 beta 形式推出并有额外定价，说明其成本结构与 200K 不同，大概率也采用了类似的混合方案。

**（2）深度：让 100+ 层的网络可训练。**

- **mHC（流形约束超连接）**：Hyper-Connections 用可学习的混合矩阵替代残差连接以提升表达力，但在深网络中数值会发散。mHC 把混合矩阵约束到 Birkhoff 多面体（双随机矩阵）上，用 Sinkhorn-Knopp 迭代投影，保证谱范数 ≤ 1，从而深度可扩展。DeepSeek V4 使用 mHC（hc_mult = 4）。
- **Attention Residuals（Kimi K3）**：让每一层不只看上一层输出，而是对之前所有块的输出做注意力加权（Block AttnRes，每 8 层一块）。这是"跨深度的注意力"，缓解深网络中信息衰减。

两者本质相同：**残差连接从固定的恒等映射变成可学习、有约束的信息路由**。

**（3）宽度：MoE 稀疏度推到 50 以上。**

Kimi K3 的 Stable LatentMoE：896 个专家中每 token 激活 16 个（稀疏度 56），通过潜空间路由（先投影到低维 latent 再路由）与 SiTU-GLU 激活、Quantile Balancing 负载均衡保证稀疏度极高时训练稳定。DeepSeek V4-Pro 1.6T/49B（稀疏度约 33）、Qwen3.8-Flash-Next 125B 主干仅激活 6B。**总参数继续增长，激活参数反而收敛在 6B–100B 区间**——这是为什么 2.8T 的 K3 只需 64 张加速卡即可服务。

**（4）记忆：把"知道"从"计算"中剥离。**

Engram 是 2026 年国产架构最重要的原创贡献。核心观察：Transformer 用注意力和 MLP 同时承担"推理"和"记忆"，但记忆（比如某个 N-gram 后面通常接什么）不需要计算，只需要查表。Engram 引入条件记忆模块：根据当前 N-gram 哈希做 O(1) 查找，取出的向量与隐状态融合。论文发现 **MoE 参数与记忆参数之间存在 U 型 scaling law**——两者按一定比例配置时效果最优，全部投给 MoE 或全部投给记忆都次优。27B 验证：MMLU +3.4、BBH +5.0、NIAH 84.2 → 97.0。工程上记忆表可放在主机内存并预取，不占显存。

Qwen3.8-Flash-Next 的"51B N-gram 嵌入表 + 6B 激活主干"是这条路线的第二次大规模验证，训练成本仅为前代旗舰的 1/9。**这与本系列第四篇"模型原生知识体系"的判断在架构层面呼应：知识供给正在从上下文注入下沉到参数化的外置记忆。**

**（5）精度与优化器：FP4 训练与 Muon。**

DeepSeek V4 与 Kimi K3 均采用 FP4 / MXFP4 量化感知训练（QAT），推理时直接以 4 位权重服务而无精度损失；均使用 Muon 优化器（K3 是 Per-Head Muon），DeepSeek 首次在 1.6T 规模验证 Muon。DeepSeek V4 还实现了确定性 kernel（同输入同输出），这对 on-policy RL 的可复现性至关重要。**数值精度与优化器不再是训练细节，而是决定同等算力下能训多大模型的一等变量。**

#### 2.2.3 可验证的信号

- 1M 上下文的定价是否与 200K 同价（同价意味着混合注意力已成熟）。
- 厂商是否公布 KV cache 占比、激活参数数。
- 长上下文质量指标（MRCR v2、NIAH 多针）是否随长度平缓下降而非断崖。

### 2.3 主线三：effort 可控化与 token 效率成为竞争主轴

#### 2.3.1 矛盾

推理时计算证明"想得更久更准"，但代价是 token 用量与延迟不可控。用户需要的是**同一模型在简单任务上快而便宜、在困难任务上深而可靠**，并且这个选择权在调用方而不在模型。

#### 2.3.2 机制：从训练侧到 API 侧的完整链路

**（1）训练侧：按 effort 分档训练再蒸馏。** Kimi K3 的 3 × 3 = 9 个 RL 专家中，effort 维度的三档各自有不同的 token 预算，**超预算奖励 −1** 是硬约束；MOPD 蒸馏后的统一模型在推理时通过系统级 effort 参数激活对应行为模式。这意味着 effort 不是简单的"截断思维链"，而是模型学会了在不同预算下采用不同的解题策略。

**（2）API 侧：effort 成为标准参数。** Opus 4.6 四档、Opus 4.7 加 xhigh、DeepSeek V4-Pro-0813 三档、Grok 4.6 xhigh、Fable 5.1 per-message effort（同一会话内逐消息调整）。OpenAI 的 Programmatic Tool Calling 让模型用代码批量调用工具，避免每次调用往返一次上下文，是另一种形式的 token 节约。

**（3）adaptive thinking：模型自己决定想多久。** Opus 4.6 的 adaptive thinking 让模型根据任务难度自主决定思考长度，effort 只设上限。这把"要不要深想"的判断从调用方交回模型，需要训练时有对应的难度感知奖励。

**（4）两种战略取向。** OpenAI 与 Anthropic 走"同分少 token"（GPT-5.5 vs 5.4；Sol 比 Fable 5 少一半 token）；Google 的 Gemini 3.8 Flash 走"多 token 换分数"（输出多 30%，"works harder"）。前者面向 agent 长会话的成本敏感场景，后者面向低价模型冲榜。**两条路线都在承认同一件事：token 效率是与分数并列的核心指标。**

#### 2.3.3 经济学背景

Gartner 8 月提出"推理悖论"：token 单价到 2030 年预计下降 95%，但 agentic 工作流的推理总成本到 2028 年增长 5 倍以上，因为 agent 每任务消耗 5–30 倍 token、reasoning 模式每任务最高 150 倍。Goldman 预计 2026–2030 年 token 消耗增长 24 倍；2026 年推理 IaaS 支出（$23.3B）已超过训练（$19B）。**当推理成本超过训练成本，effort 与缓存设计就成为模型厂商的利润来源，也成为用户的成本主变量。**

### 2.4 主线四：Harness 成为能力的第二来源，模型与 harness 共演化

#### 2.4.1 矛盾

模型的能力是"潜能"，harness 决定了多少潜能能被释放：上下文如何管理、工具如何暴露、子任务如何拆分、失败如何恢复。2026 年的观察是：**同一模型换 harness，长程任务成功率可以差一倍**；而 harness 层的创新速度已经超过模型层。

#### 2.4.2 机制：harness 的九个组件与三种分离模式

对 Claude Code、Codex、OpenClaw、Hermes、DeepSeek Harness 等 11 个主流 harness 的源码研究（arXiv 2609.00006）给出了当前 harness 的共性结构：

| 组件 | 职责 | 典型实现 |
|---|---|---|
| Loop engine | 观察 → 思考 → 行动的主循环，含终止条件 | DeepSeek Harness 的 `@deepseek-ai/dsh-agent-loop` 是唯一被单独打包的 loop |
| Context compaction | 上下文接近上限时压缩历史 | Opus 4.6 服务端 compaction；Codex 跨上下文窗口 notes |
| Tools / skills registry | 工具与技能的注册、发现、加载 | 9/11 采用 Agent Skills（SKILL.md），8/11 支持 MCP |
| Sub-agent | 派生子 agent 处理子任务，隔离上下文 | Claude Code agent teams；GPT-5.6 `ultra` 默认 4 个并行 agent |
| Built-in skills | 内置的高频技能（如 git、测试） | — |
| Session persistence | 会话状态持久化与恢复 | — |
| Dynamic system prompt | 按环境动态拼装系统提示 | — |
| Lifecycle hooks | 在关键节点插入用户逻辑 | DeepSeek Harness 事件如 `agent/pre-step`、`tools/pre-execute` |
| Permissions | 工具调用的权限门控 | — |

该研究的三个反直觉发现：**无一依赖 LangChain 等通用框架**（全部自研 loop）；**无一使用向量检索**（用文件系统 + grep + skills 替代 RAG，与本系列第四篇判断一致）；**Skills 的采用率（9/11）高于 MCP（8/11）**，ACP（编辑器-agent 协议）6/11。

三种主流分离模式：planner / executor（规划与执行分离）、writer / reviewer（写与审分离）、initializer / coder（环境初始化与编码分离）。分离的目的都是**用不同的上下文与提示让同一模型扮演互补角色，避免单一上下文中的目标漂移**。

#### 2.4.3 三个标志性演化

**（1）模型开始编排 harness：dynamic workflows。** Opus 4.8 引入 dynamic workflows：模型自己写 JavaScript 编排脚本，调度数十到数百个子 agent（社区称 `ultracode`）。这与 OpenAI 的 Programmatic Tool Calling 同构——**编排逻辑从 harness 硬编码变为模型生成的代码**，harness 只提供运行时。Claude Managed Agents 进一步把 harness 托管化（memory、dreaming、outcomes 作为服务能力）。

**（2）应用厂商在自家 harness 中训练模型。** Cursor Composer 2 基于 Kimi K2.5 继续预训练，然后在真实 Cursor harness 中做 RL；Kimi K3 反其道而行——在训练环境中随机切换 harness 以防过拟合。两者从相反方向确认了同一事实：**harness 是训练分布的一部分**。模型在哪个 harness 里训练，就在哪个 harness 里表现最好。

**（3）协议标准层成型。** MCP 2025 年 12 月捐给 Linux Foundation 的 AAIF；Agent Skills 成为事实标准；SEP-2640 "Skills over MCP"（`skill://` URI）让技能可通过 MCP 分发，OpenAI 8 月以快照方式先行采用；Agent Plugins 1.0.0（8/6）；ACP 由 Zed / JetBrains 推进。DeepSeek Harness v0.1 的 Cordis 微内核、"everything is a plugin"、可把 Claude Code / Codex 作为子 agent 驾驭，是"harness 之上的 harness"的第一个国产实现。**"从工具到平台"是这一层的主叙事。**

#### 2.4.4 可验证的信号

- 模型公告中 harness 功能所占篇幅（Opus 4.6 公告中一半以上讲 compaction、agent teams）。
- 同一模型在不同 harness 中的 benchmark 差异是否收敛。
- 协议采用率（Skills、MCP、ACP）与 marketplace 规模。

### 2.5 主线五：记忆与持续学习——尚未突破的最后一环

#### 2.5.1 矛盾

上述四条主线让 agent 能完成更长、更复杂的一次性任务，但**agent 仍然不会"越用越好"**。每次会话从零开始，用户纠正过的错误下次照犯。真正的持续学习（改权重）在安全、成本、灾难性遗忘上都未解决，因此 2026 年所有"自进化"都发生在 harness 层。

#### 2.5.2 机制：四个层级的"记忆"

| 层级 | 机制 | 代表 | 是否改权重 |
|---|---|---|---|
| **文件记忆** | agent 把经验写入文件，下次会话读取 | Fable 5 在 Slay the Spire 上用文件记忆取得 3 倍增益；Codex 跨上下文窗口 notes | 否 |
| **技能沉淀** | 把重复成功的操作序列固化为 SKILL.md | Hermes Agent（130k+ stars，四层记忆，自动生成技能）；hermes-agent-self-evolution 用 DSPy + GEPA 离线演化提示与技能 | 否 |
| **harness 自改** | agent 对自己的 harness 做 reset-free 的 CRUD | Continual Harness（arXiv 2605.09998）：agent 增删改自身的工具、提示、流程，并联合 PRM / DAgger soft SFT 训练 | 部分（联合训练时改） |
| **权重内记忆** | 在架构中引入可在推理时更新的记忆参数 | Nested Learning / Hope / Titans（研究阶段）；Engram 的条件记忆是静态版本 | 是 |

需要澄清一个常见误读：豆包 `doubao-seed-evolving` 是一个固定 model ID，背后权重按周滚动替换为最新版本（当前 = Seed 2.1 Pro），**是运维层的滚动发布，不是在线权重学习**。

#### 2.5.3 现场学习的硬指标：ARC-AGI-3

ARC-AGI-3 是交互式基准，要求 agent 在陌生环境中通过试错现场学会规则。6 月 30 日的结果：Opus 4.8 仅 1.5%，OpenClaw + Opus 4.7 组合 5.2%。而 9 月 3 日 GPT-6 Astra 宣称"96% 关卡达到人类效率"——两个数字口径不同（前者是总分，后者是按关卡计的效率达成率），但即使打折看，两个月内的跨越也说明 OpenAI 在"环境中学习"上投入了针对性训练。这是**值得重点跟踪的最前沿信号**：如果 ARC-AGI-3 类任务被系统性攻克，意味着 RL 已经教会模型"如何学习"，持续学习的门就被推开了一半。

#### 2.5.4 安全代价：OpenClaw 的教训

harness 层的记忆与技能沉淀带来新的攻击面：OpenClaw 累计 169 条安全通告；ClawHavoc 供应链事件涉及 341–1467 个恶意 skills；135k 个实例暴露在公网；Claw Chain 漏洞 CVE-2026-44112 达 CVSS 9.6。prompt-injection 竞技场数据显示模型间差异巨大（Opus 4.5 攻击成功率 0.5% vs Gemini 2.5 Pro 8.5%）。**技能是可执行代码，技能市场就是软件供应链**，这一层的安全成熟度远低于其采用速度。

## 三、格局与产业

### 3.1 开源与闭源：差距稳定在 3–6 个月，但披露度反转

从 benchmark 看，DeepSeek V4 Preview（4 月）对标的是 GPT-5.4 / Opus 4.6 级别（2–3 月），V4-Pro-0813 在 Terminal-Bench 2.1 上 87.9 已超过 Sonnet 5（80.4）与 Opus 4.8（74.6），Kimi K3 在 WebDev Arena 登顶。**差距在 3–6 个月且没有扩大**。

但值得注意的是两个反向趋势：
- **披露度反转**：闭源厂商 2026 年几乎不再披露任何架构与训练细节，而 K3 的 47 页报告、DeepSeek V4 的完整架构说明是理解这一代技术的唯一一手来源。**开源模型的技术报告是我们反推闭源机制的主要依据。**
- **国产开源开始"半开"**：DeepSeek V4-Pro-0813 未放权重、峰时价格涨 4.5×；Qwen3.8-Max 仅放文本权重。最强版本商业化、次强版本开源，正在成为国产厂商的标准策略。

### 3.2 国产路线：效率优先与办公 Agent 大战

**技术路线上，国产模型形成了明显的共性配方**：超大总参数（1.6T–2.8T）× 极低激活（6B–104B）× FP4/MXFP4 QAT × Muon 优化器 × 条件记忆（Engram / N-gram 嵌入表）× 稀疏或线性注意力。每一项都指向同一目标：**在算力受限条件下最大化每 FLOP 的能力**。Qwen3.8-Flash-Next 以前代旗舰 1/9 的训练成本达到接近性能，是这条路线最极端的验证。

**产品路线上，国内竞争重心在 8 月集中转向办公 Agent**。QwenWork（3000 万用户/月）、豆包工作（68 元/月，整合 TRAE / 扣子 / 飞书）、Kimi Work、腾讯 WorkBuddy、金山灵犀、百度 DuMate 在同一个月上线。它们的共同特征：多 agent 并行、操作电脑（CUA）、多模型可切换、按积分计费。这一波的本质是**把 harness 层做成消费级入口**，与美国以开发者工具（Claude Code、Codex、Cursor）为入口形成对照。

### 3.3 安全：从红线到架构组件

2026 年的四个事件共同改变了安全的位置：

1. **Mythos Preview 不发布**（4 月）：首次出现"能力太强所以不公开"的前沿模型，通过 Project Glasswing 定向提供给 40+ 机构做防御。截至 9 月它已发现 26,000+ 漏洞，但修复率 <1%——**发现能力已远超修复能力**，这本身是新的系统性风险。
2. **GPT-6 Astra Critical 级**（9 月）：首个在 Preparedness 框架下被评为网络风险 Critical 的模型，ExploitBench 100%，同时 OpenAI 承认其推理链更难监控。Daybreak 计划是对应的防御倡议。
3. **分类器门控成为发布架构**：Fable 5 用分类器识别高风险请求并回退到 Opus 4.8，>95% 会话无回退。**一个"模型"实际上是一个模型对 + 分类器的系统**，这对延迟、一致性、可解释性都有影响。
4. **Hugging Face 事件**（7 月）：攻击者利用内部模型与 GPT-5.6 Sol 生成的数据集投毒，获得训练节点权限并窃取凭证；OpenAI 暂停 RL 训练约两周、搁置最大 RL run，8/26 发布技术报告，METR / Redwood 独立评审。这是**首个针对训练流水线本身的供应链攻击**，说明训练数据的来源验证成了安全边界。

### 3.4 AI 参与 AI 研发：递归加速已是公开事实

- Anthropic 5 月披露 >80% 合并代码由 Claude 编写；kernel 优化加速比从 Opus 4（2025/5）的 3× 到 Mythos Preview（2026/4）的 52×；自主研究任务恢复能力评测中模型达到人类 97%（人类基线 23%，800 小时 / $18k）。
- OpenAI 披露 GPT-5.6 Sol 独立完成了 Luna 的后训练；RSI 指数 +16.2；Pachocki 宣布"automated research intern"里程碑达成，目标 2028 年 3 月实现全自动 AI 研究员。
- METR 时间地平线 TH1.1：自 2024 年起倍增期 88.6 天；但 >16 小时的任务已无法可靠测量——**评测手段跟不上能力增长**。

这条线对架构师的意义不在于科幻式的想象，而在于一个务实推断：**当模型参与自身后训练，代际迭代速度会继续压缩，6 周的节奏不会放缓**。规划技术栈时应假设每季度有一次能力台阶。

### 3.5 具身：多模态 agent 向物理世界延伸

Gemini Robotics 2 / ER 2（7/30，基于 Gemini 3.5 Flash，配套 ASIMOV-Agentic 安全基准）、Fable 5 仅用视觉 harness 通关 FireRed，说明 CUA（计算机使用 agent）与机器人共享同一套"感知 → 规划 → 行动"的 agentic RL 方法论。OSWorld 2.0 上 GPT-6 Astra 72.6%（约 40 分钟）vs GPT-5.6 Sol 65.7%（约 75 分钟），CUA 在效率维度的提升与编码 agent 同步。

## 四、未来 12–24 个月的方向研判

以下判断按"确定性"从高到低排列，并标注可用于验证的观察点。

### 4.1 模型层

**（1）混合注意力成为默认，全注意力退化为"少数关键层"。** 三条稀疏路线（压缩选择、线性化、块稀疏）将收敛为混合配方；1M 上下文的定价将与 200K 趋同；"10M 上下文"会在 2027 年上半年出现在开源模型中。观察点：厂商是否取消长上下文附加费。

**（2）条件记忆（Engram 路线）进入闭源模型。** Qwen4 架构预览已采用，DeepSeek 下一代必然采用；闭源模型大概率已在使用但不披露。观察点：模型在事实性问答上的提升是否与推理能力提升脱钩（脱钩即记忆模块独立扩展的信号）。

**（3）激活参数收敛于 10B–100B，总参数继续增长至 5T–10T。** 稀疏度 50+ 已被 K3 验证稳定，训练成本 1/9 的 Flash-Next 会促使所有厂商重做参数配比。观察点：新模型公布的"激活/总参数"比。

**（4）模型分层从"三档"变为"底座 + 可组合能力包"。** 效率轴（Sol/Fable 路线）与冲榜轴（Gemini Flash 路线）会分化出不同定价逻辑；分类器门控的双模型架构会普及到所有前沿发布。观察点：API 是否开始暴露"回退率"或"路由到哪个子模型"。

### 4.2 训练层

**（5）环境工程工具链独立化，出现"环境即服务"。** ToolVerse、NeMo Gym、VeriGen 类框架会商业化；企业私域环境（自己的代码库、内部系统 mock）会成为微调的新形态——**不是喂数据，而是喂环境**。观察点：云厂商是否推出 RL 环境托管产品。

**（6）on-policy 蒸馏与多教师蒸馏成为小模型的标准生产方式。** K3 的 MOPD、DeepSeek 的 on-policy distillation 说明"训 N 个专家再蒸馏"比"直接训一个全能模型"更稳。观察点：小模型公告中是否明确列出教师模型。

**（7）训练流水线安全成为独立学科。** Hugging Face 事件后，数据来源签名、合成数据审计、训练节点隔离会成为前沿实验室标配。观察点：是否出现训练数据供应链的行业标准。

### 4.3 智能体层

**（8）harness 平台化，编排逻辑由模型生成。** dynamic workflows / Programmatic Tool Calling 会成为所有主流 harness 的默认；harness 之间通过 ACP / Skills over MCP 互操作；"harness 驾驭 harness"（DeepSeek Harness 驾驭 Claude Code）会普及。观察点：harness 是否开始公布"可被作为子 agent 调用"的接口。

**（9）模型与 harness 的绑定加深，出现"模型专用 harness"与"harness 专用模型"两极。** Composer 2 路线（在自家 harness 训模型）会被更多应用厂商复制；同时开源模型会像 K3 那样在多 harness 中训练以保持通用。观察点：应用厂商是否公布自训模型。

**（10）记忆从文件层走向参数层，2027 年出现首个可信的"会越用越好"的 agent。** 路径大概率是：文件记忆 → 技能沉淀 → 可训练的外置记忆（Engram 的动态版本 / Titans 类）→ 有限的在线权重更新。ARC-AGI-3 是这条线的风向标。观察点：ARC-AGI-3 总分是否在 12 个月内突破 30%。

**（11）多 agent 从"并行加速"走向"角色分工的组织"。** 当前的 agent teams / `ultra` 4 并行主要是吞吐加速；下一步是 planner / executor / reviewer 之外更细的角色（安全审计、成本控制、用户代理），以及 agent 间的协商协议。观察点：是否出现 agent 间的标准化协商 / 仲裁协议。

### 4.4 部署与经济层

**（12）成本核算单位从"每百万 token"变为"每任务完成"。** tokenizer 税、effort、缓存三个隐性变量会迫使行业采用任务级计价；Gartner 的推理悖论会在 2027 年进入企业预算讨论。观察点：主流厂商是否推出按任务/按结果计费。

**（13）推理基础设施向"长会话优化"倾斜。** KV cache 持久化、跨请求缓存、外置 KV pool 会成为推理引擎的核心竞争点（K3 的 1M RL 已依赖外置 KV pool）。观察点：vLLM / SGLang 类引擎的 roadmap。

### 4.5 安全与治理层

**（14）能力门控成为发布的标准阶段，"不公开发布"会常态化。** Mythos 与 Astra 的先例说明：最强模型将首先服务于防御方，公开版本落后 3–6 个月。这会**让"闭源最强 vs 开源最强"的实际差距比公开 benchmark 显示的更大**。观察点：Project Glasswing / Daybreak 类计划的扩展。

**（15）漏洞发现远超修复能力，会催生"AI 修复 agent"的专门市场。** 26,000+ 发现、<1% 修复，这个缺口是明确的产品机会，也是系统性风险。观察点：是否出现专门做补丁生成与验证的 agent 产品。

**（16）技能供应链安全立标。** ClawHavoc 之后，技能签名、沙箱执行、权限声明会进入 Skills 规范。观察点：Agent Skills 规范是否加入签名与权限字段。

### 4.6 国产路线

**（17）"最强版本闭源、次强版本开源"成为标准策略。** DeepSeek V4-Pro-0813 不放权重、Qwen3.8-Max 只放文本权重已是先例。国产开源会继续以 3–6 个月差距领跑开源世界，但最强能力将通过 API 商业化。

**（18）办公 Agent 大战的胜负由"环境接入深度"决定，而非模型。** QwenWork / 豆包工作 / WorkBuddy 的差异化最终取决于对企业系统（OA、ERP、IM、文档）的连接深度与权限模型，本质是 harness 层与生态层的竞争。观察点：各家开放的企业连接器数量与权限粒度。

**（19）效率路线会反向输出到国际。** Engram、mHC、KDA 混合注意力这类降本机制会被闭源厂商吸收（大概率已在发生）；FP4 QAT + Muon 会成为全球默认训练配方。

## 五、给架构师的行动建议与"主动感知"信号清单

### 5.1 阅读框架：四层栈

每读到一条新闻，先归入四层中的一层，再问"它是否改变了该层的主线判断"：

| 层 | 主线判断（2026-09） | 会改变判断的信号 |
|---|---|---|
| **架构** | 混合注意力 + 超深可训练 + 极稀疏 MoE + 条件记忆 + FP4 | 全注意力回归；激活参数重新增长；记忆模块被放弃 |
| **后训练** | agentic RL + 环境工程 + 多专家蒸馏 + effort 预算奖励 | 预训练 scaling 重新成为主要提升来源；RL 环境被证明不可扩展 |
| **Harness** | 九组件结构、模型生成编排、Skills > MCP、模型-harness 共演化 | 通用框架（LangChain 类）重新主导；向量检索回到 harness 核心 |
| **部署经济** | 效率轴竞争、任务级成本、缓存定价、门控双模型 | token 标价重新成为唯一变量；门控架构被取消 |

### 5.2 技术选型建议

1. **模型选型用"任务级总成本"而非标价**。自建一个代表性任务集（10–20 个真实工作流），对候选模型在相同 harness 下跑通并记录总 token 费用、成功率、耗时。tokenizer 差异（1.3× 甚至更高）与 effort 设置对成本的影响常大于标价差异。

2. **harness 选型看"可训练性"与"互操作性"两个维度**。可训练性：能否以低成本从 harness 中导出轨迹用于后续微调 / 环境构建；互操作性：是否支持 Skills、MCP、ACP，能否被其他 harness 作为子 agent 调用。避免把业务逻辑写进任何一家 harness 的私有插件系统。

3. **私域知识投入优先做"环境"而非"数据"**。承接本系列第四篇的判断：把企业系统 mock 成可交互的 RL 环境（有验证器的任务集），比整理 QA 对更有长期价值——它既可用于评测，也可用于未来微调，还可直接作为 agent 的测试床。

4. **记忆层用文件 + 技能沉淀，暂不押注在线学习**。Hermes / Continual Harness 类方案已可落地；权重层持续学习 12 个月内不会成熟到可用于生产。但要为记忆的**审计与回滚**留出设计（技能是可执行代码）。

5. **安全架构预设"门控 + 供应链"两道线**。对接前沿模型时预期会遇到回退与拒答，设计上要能容忍"同一请求不同子模型响应"的一致性问题；对技能 / 插件市场按软件供应链管理（签名、沙箱、最小权限）。

6. **规划节奏按"每季度一个能力台阶"**。不要为某一代模型做深度优化；把能力假设参数化（上下文长度、effort、并行 agent 数），让系统在下一代到来时只改配置。

### 5.3 "主动感知"信号清单

按优先级排列，每项标注跟踪来源与判读方式：

| 优先级 | 信号 | 来源 | 判读 |
|---|---|---|---|
| 高 | 开源模型技术报告（DeepSeek、Kimi、Qwen、MiniMax） | arXiv、GitHub | 唯一能看到架构与后训练细节的一手材料；重点读 RL 环境章节与 ablation |
| 高 | ARC-AGI-3 榜单 | arcprize.org | 现场学习能力的唯一硬指标，突破 30% 即记忆 / 持续学习进入新阶段 |
| 高 | 长程评测（Terminal-Bench、OSWorld、LongHorizon 系列） | 各基准官方 | 关注"成功率 × 耗时 × token"三元组而非单一分数 |
| 高 | 模型公告中的定价结构变化（缓存、effort、长上下文附加费） | 厂商 pricing 页 | 定价变化直接反映架构成本变化 |
| 中 | Harness 源码 release notes（Claude Code、Codex、DeepSeek Harness、OpenClaw、Hermes） | GitHub | 看新增组件属于九组件中的哪一个；编排是否由模型生成 |
| 中 | 协议规范演进（Agent Skills、MCP SEP、ACP、Agent Plugins） | 规范仓库 | 采用率与签名 / 权限字段的加入 |
| 中 | RL 环境框架（ToolVerse、NeMo Gym、VeriGen 类） | GitHub、论文 | 环境数量、工具数量、验证器类型 |
| 中 | 安全事件与门控计划（Glasswing、Daybreak、Preparedness 评级） | 厂商安全页、METR | 评级变化预示公开版本与最强版本的差距 |
| 中 | METR 时间地平线 | metr.org | 倍增期变化；测量上限（当前 16 小时）是否被突破 |
| 低 | Arena 类主观榜单 | LMArena 等 | 只作辅助，易受风格影响 |
| 低 | 用户量 / 融资 / IPO 新闻 | 媒体 | 判断产品层竞争，不反映技术层 |

### 5.4 回到最初的问题

"能看到效果、看不到机制"的根本原因是：这一轮变革的机制分散在四层，且最关键的两层（后训练、harness）披露最少、产品化包装最重。解决办法不是追更快，而是：

- **用开源报告反推闭源**：K3 / V4 的报告就是理解 Fable / Astra 的最好教材，因为它们解决的是同一组矛盾（长上下文成本、长程可靠性、effort 可控、harness 鲁棒）。
- **用定价反推架构**：长上下文是否加价、缓存怎么算、effort 档位如何设计，都是成本结构的外显。
- **用评测三元组反推训练**：成功率、耗时、token 同时提升的只能是 RL 训练侧的改进；只有分数提升而 token 增加的是推理时计算的堆叠。
- **用 harness 变化反推模型能力边界**：harness 新增的每个组件，都是在补模型当前做不到的事；harness 删掉的组件，说明模型已经内化了这项能力。

掌握这四个反推工具，就能从被动跟进转为主动判读。
